# RAG：让回答带着资料依据

## 一、把外部资料接到生成过程

RAG 是检索增强生成的常见简称。一个典型系统先从外部资料中检索相关片段，再把问题和片段交给生成模型组织回答。课程笔记会不断增补，项目文档也会更新；通过检索接入资料，可以在不重新训练语言模型的情况下，让本次回答读取新内容。这里的“增强”指补充上下文，不能理解为自动消除了所有幻觉。

可以把它想成开卷回答：先找到相关页面，再依据页面作答。开卷仍可能找错页、漏看限定条件或误解证据。因此，一个完整系统需要关心资料质量、检索质量、回答忠实程度和引用可追溯性。只展示一段流畅答案，无法说明这几个环节都已经可靠。

## 二、离线入库：为资料建立可检索表示

### 2.1 解析与切分

系统先从文件提取文字，保留来源标题、页码或章节等位置。随后将长文切为较小的块。块太短可能缺少定义与条件，块太长则会稀释主题并占用上下文。适当重叠能保留段落交界处的信息，但也会增加存储与重复内容。不存在适合所有材料的固定最佳块长，需要根据文档结构和问题类型评估。

知页当前采用约五百字目标块长和八十字重叠，并让块不跨越 PDF 页、幻灯片或工作表等既定分节。这是项目的实现选择，并非所有 RAG 系统都必须遵循的标准。若一条结论跨越两页，检索和回答仍需处理相邻证据；保存位置有助于人回到原件核对。

### 2.2 向量化与保存

嵌入模型把文字编码成固定维数的数值向量。经过合适训练的模型，通常会把语义相关文本映射到较相近的位置。数据库保存分块原文、位置、归属和向量。向量不是正文的可读摘要，也通常不能直接反推出完整原文。系统仍需保留文字，供回答与引用使用。

## 三、在线问答：从问题找到证据

| 阶段 | 输入 | 输出与检查重点 |
|---|---|---|
| 问题编码 | 用户问题 | 与资料处于兼容空间的向量 |
| 范围过滤 | 用户、笔记本、所选来源 | 排除不应访问的材料 |
| 相似度检索 | 问题向量与候选块 | 若干相关候选片段 |
| 上下文组织 | 片段、标题与位置 | 可追踪的编号证据 |
| 生成与核对 | 问题和证据 | 回答、引用及资料不足说明 |

检索范围必须先符合权限约束。不能先从全站资料找相似段落，再寄希望于回答阶段隐藏他人内容。知页按当前用户、笔记本、选中来源和就绪状态限制候选块。这样的隔离是数据访问规则，与向量相似度高低无关；再相似的他人资料也不应进入当前问题的上下文。

## 四、理解余弦相似度与 Top-K

余弦相似度比较向量方向：两个非零向量的点积除以各自长度的乘积。它的数学取值范围为负一到一，实际分布与模型有关，不能把零点八直接解释成“答案有八成正确”。数据库也可能使用一减余弦相似度作为距离，此时数值越小表示越近。阅读指标时要先弄清楚它表示相似度还是距离。

Top-K 表示取排序最靠前的若干候选。K 太小可能漏掉重要条件，太大可能引入噪声与重复。关键词检索擅长精确术语、编号和专有名称，向量检索有助于发现表达不同但语义相关的内容；实际系统可以组合使用，也可以增加重排序。不能仅凭“用了向量数据库”就推断检索一定优于关键词方法。

## 五、更换嵌入模型为什么要重建

同样的维数不意味着同样的向量空间。两个模型都输出一千多个数，它们各维度的含义与分布仍可能不同。如果旧资料用模型甲编码，新问题用模型乙编码，相似度就可能失去原有意义。更换嵌入模型后，应让已有分块与新问题使用兼容表示，通常需要重建全部资料向量。

重建可以保留原文、来源和位置，只重新计算向量。模型调用可能消耗费用或额度，因此应记录进度、处理失败并保证数据一致。知页的精选示例先由系统模板完成入库，用户添加时复制已有向量，避免为每位体验者重复计算同一组材料；更换模型后的全量重建也需要覆盖模板。

## 六、如何评估一个小型 RAG 系统

先为一组真实问题标出应该找到的证据，再分别检查检索和回答。检索检查“需要的片段是否进入候选”，回答检查“关键结论是否由提供的证据支持”。两个环节要分开：没有找到证据时，生成模型不应被要求凭空补齐；已经找到正确证据但回答误读时，则需要改进上下文组织或生成约束。

测试集可包含直接定义题、跨段比较题、带精确编号的查找题、冲突来源题和无答案题。记录问题、期望证据、检索结果、回答与人工判断。为了公平比较参数，不要每次随意更换问题，也不要用已反复调优的题目冒充独立评测。小型毕业设计可以先做少量可复核样本，把评价口径说明清楚。

引用能提升可检查性，但编号正确不等于事实正确。最终要核对原文是否支持回答、引用是否遗漏条件、资料是否适用于当前任务。RAG 的价值在于把回答与可阅读的证据联系起来，让学习者更容易发现和纠正问题，而不是用技术名称代替人工判断。
