# T3 交付说明：RAG 问答与 SSE 流式输出

状态：已完成。日期：2026-11-14。

## 完成内容与关键文件

- `backend/internal/service/chat/chat.go`：对话准备、问题向量化、复用 T2 Retriever 的 Top-K 检索、读取用户模型与回答风格、流式生成、消息持久化、反馈及清空。笔记本与来源均按用户隔离；不存在或属于其他笔记本的来源返回 404，未 ready 来源返回 400。空来源不调用 Embed/ChatStream，仍依次发送 citations、提示文字和 done，并保存两条消息。
- `backend/internal/service/chat/citations.go`：默认 Top-K 为 6，丢弃余弦相似度低于 0.2 的片段。同一来源的相邻块按原文顺序合并，去掉最多 80 字重叠；按合并组首次出现在检索结果的位置编号。quote 按 Unicode 字符截取前 150 字，折叠换行和空白。保存时只保留正文实际出现的 `[n]`，保持原编号，不重新编号。
- `backend/internal/rag/prompt.go`：只依据本轮资料、逐句引用、资料不足时说明、中文 Markdown、不得编造编号等系统要求；最近 6 轮历史；concise/detailed/learning 三种风格。检索上下文和历史分开，历史引用不作为本轮编号依据。
- `backend/internal/handler/chat.go`：注册五个对话/概要接口，严格校验请求，消息响应仅输出契约字段。SSE 使用单行 JSON `data: ...\n\n`，显式设置 `Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`，每个事件 Flush；空 citations 编码为 `[]`。
- 生成成功时先发送 citations，再发送各 delta；assistant 消息落库成功后才发 done，messageId 为数据库中的真实 UUID。模型或检索失败发送中文 error，已生成内容仍保存。客户端断开后请求上下文传递到 LLM，立即停止生成；持久化使用独立的 5 秒超时上下文，并记录停止生成与保存字符数的日志。
- `backend/internal/service/chat/guide.go`：有效概要直接读缓存；stale 时基于全部 ready 来源摘要生成 120～220 字中文概要及 3 个问题，无 ready 来源返回空。singleflight 按用户和笔记本合并并发请求，单个等待者取消不影响其他等待者。保存前获取与 T2 相同的笔记本行锁，复核 ready 来源的 ID、标题、摘要和更新时间；发生变化重新生成，最多 3 次，防止旧结果覆盖失效标记。
- `backend/internal/llm/notebook_guide.go`、`fake.go`：概要 JSON 构造、长度/中文/问题数量及去重校验、格式失败时按来源摘要摘录降级；Fake 输出相同结构。Fake 问答只读取本轮检索上下文，并以每字约 3ms 的节奏流式返回，便于离线演示停止生成。
- `backend/cmd/server/main.go`：注入共用的 LLM 客户端、Retriever 与对话注册器。`golang.org/x/sync` 从间接依赖调整为直接依赖，版本未变。

## 接口

所有路径均继承现有 JWT 鉴权；成功的普通响应仍为 `{code:0,data:...,message:"ok"}`。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/notebooks/:id/messages` | 正序历史，空列表为 `[]` |
| DELETE | `/api/notebooks/:id/messages` | 清空当前用户该笔记本消息，data=null |
| POST | `/api/notebooks/:id/chat` | citations → delta… → done；失败发 error 后结束 |
| POST | `/api/messages/:id/feedback` | value 为 up/down/null，支持清除反馈 |
| GET | `/api/notebooks/:id/guide` | 概要、3 个推荐问题与缓存 |
