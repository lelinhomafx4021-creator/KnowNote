# T7 交付说明：多格式文档解析、原件预览与阿里云 OSS 存储

状态：已完成。日期：2026-11-14。

## 完成内容与关键文件

- `backend/internal/parser`：解析结果增加完整 sections、pageCount 与截断说明。PDF 逐页解析；PPTX 按 `presentation.xml` 和 relationships 顺序解析标题、正文列表、Markdown 表格与演讲者备注；DOCX 识别 Heading、继承样式及 outlineLvl，按标题切节，保留列表和表格，无标题正文也公开 section；XLSX 使用 excelize，CSV 自动识别 UTF-8/GBK 及逗号、分号、制表符、竖线分隔。每张工作表最多读取 2000 行数据（另加列名行），截断写 summary，不污染 error。
- `parser/office_convert.go`：统一 LibreOffice 转换。`SOFFICE_PATH` 优先，未设置时依次查 PATH 的 soffice/libreoffice 和指定 macOS 路径；每次使用独立临时 UserInstallation 目录、headless convert-to，120 秒预算（包含并发等待）、全进程并发上限 2。旧 DOC/PPT/XLS 转为对应 OOXML 后解析，保留 originalExt，type 使用 docx/pptx/xlsx。
- `internal/model`、`internal/service/ingest`、`internal/rag`：AutoMigrate 增加 sources 的 page_count/sections/previewable/original_ext/object_key/preview_key，chunks 的可空 page、location_label、section_index。旧 chunk 的 page 保持 NULL。每个 section 独立切分并保留位置，检索返回页码及标签；引用合并不能跨 section。Source.sections 仅公开前 120 字 excerpt，完整正文保存在来源与分块中。
- `internal/service/chat`、`rag/prompt.go`：SSE citations 增加 page/locationLabel，提示词逐段标明位置；历史消息 JSONB 同时保存，原有引用过滤仍保留这些字段。PDF 标签为“第 N 页”，PPT 为“第 N 张幻灯片：标题”，表格为“工作表：名称”。DOCX 使用章节标签，不把标题序号当作物理页码。
- `internal/handler/files.go`、`sources.go`、`studio.go`：新增来源 preview/file 路由并复用音频文件响应。先鉴权与归属校验，支持 Bearer 和 query token，有无效 Authorization 时禁止降级；local 通过 ServeContent 支持 Range，OSS 302 到 10 分钟签名 URL，响应类型及 inline/attachment 一并签名。
- `internal/storage`：Store 抽象包含 Put/Open/Delete/DeletePrefix/Stat/SignedURL；local 使用受限 os.Root 和原子写入，继续读取已有相对路径。OSS 使用官方 v2 SDK，原件、preview.pdf、MP3 统一写入存储接口；必须使用文件路径的解析步骤先下载到独立临时目录，结束后移除。来源/笔记本删除清理相关对象，OSS 清理失败持久化到 DATA_DIR/.oss-cleanup，每 5 秒重试并支持重启恢复；local 保留既有清理日志。
- `internal/service/ingest`：PDF 原件直接作为预览；Word/PPT 解析成功后转换 PDF。转换在事务锁外执行，写预览对象时重新锁定笔记本及来源，防止删除期间创建孤立预览。预览失败只记日志，正文仍 ready，previewable=false。
- `.env.example`、`internal/config`、`cmd/server/main.go`、`scripts/dev.sh`：新增 SOFFICE_PATH/STORAGE_DRIVER/OSS_*，校验驱动、必要凭据、Endpoint 与前缀；启动日志只打印驱动名称。启动脚本扩展变量白名单，继续只解析 KEY=VALUE，不执行文件。
- `backend/README.md`：补充解析边界、转换器定位、OSS 私有 Bucket、RAM 最小权限 JSON 策略、签名跳转/CORS、存储键、删除重试与测试方法。

没有修改接口契约或前端；并行 T8 的 frontend 改动未纳入本提交。

## PDF 方案评估与对比

采用 `github.com/klippa-app/go-pdfium v1.21.4` 的 webassembly 后端，运行时为纯 Go wazero；未安装任何系统软件、原生 PDFium、poppler 或 OCR 工具。依赖选择与无 CGO 运行方式见 [PDFium 官方说明](https://github.com/klippa-app/go-pdfium)。生产解析只使用 WASM；ledongthuc/pdf 留在测试中用于可重复的旧方案对比。

`internal/testfixture.PDF` 用 Go 直接生成三页中英文 PDF，包含 Type0 字体、ToUnicode 映射、英文词间空格、跨行连字符、重复页眉页脚；不依赖外部字体文件或样例下载。

| 对比项 | 原 ledongthuc/pdf GetPlainText | PDFium WASM + 清洗 |
|---|---|---|
| 同一现场生成的中英文样例 | 第一页返回 `runtime error: index out of range [1] with length 1`，没有可用正文 | 三页全部提取成功，各页中文位置与英文句子完整 |
| 页码 | 旧业务层拼接全文，未保留页码 | 三个 sections，对应 page=1/2/3、pageCount=3 |
| 连字符断行 | 样例已在文字提取阶段失败 | `The docu-` 换行 `ment contains citations.` 合并为 `The document contains citations.` |
| 重复页眉/页脚 | 旧业务没有清理 | 仅清理至少三页、出现在页面边缘的多数重复行，正文重复段保留 |
| 部署 | 纯 Go | 内嵌 WASM，无系统库/CGO；首个 PDF 需初始化编译模块，后续复用 |

对比日志由 `TestGeneratedDocuments/pdf` 输出；最终统一检查中该测试通过。PDFium 首面正文为：`第1页：知识管理与资料检索。`、`KnowNote supports multi-page retrieval.`、`The document contains citations.`。这里只报告该可重复样例的结果，没有把它视为所有 PDF 的准确率评测。保留空页 section 与原始页码；纯扫描件返回契约完整错误“未能从 PDF 中提取文字，可能是扫描件（本系统暂不支持 OCR）”。WASM 不挂载宿主文件系统，最多两个实例，取消时关闭当前实例。

## OSS 配置步骤

1. 创建地域一致的**私有** Bucket，创建专用 RAM 程序访问子账号。
2. 按 backend/README.md 的策略，仅授予指定前缀的 GetObject/PutObject/DeleteObject 和指定 uploads 前缀的 ListObjects。无需授权管理 Bucket、ACL 或列举所有 Bucket。策略结构按[阿里云官方 RAM 文档](https://www.alibabacloud.com/help/en/oss/user-guide/access-control-base-on-ram-policy)核对。
3. 通过环境变量配置 STORAGE_DRIVER=oss、OSS_REGION、OSS_BUCKET、OSS_ACCESS_KEY_ID、OSS_ACCESS_KEY_SECRET；OSS_ENDPOINT 可选，OSS_PREFIX 留空默认 knownote/。示例文件不包含任何真实凭据。
4. 保持 DATA_DIR 可写并持久化，保存 OSS 删除重试日志；启动确认日志 driver=oss。
5. 对象键严格为 `<prefix>uploads/<userID>/<sourceID>/original.<ext>`、同目录 `preview.pdf`、`<prefix>audio/<userID>/<notebookID>.mp3`。浏览器只在后端验证归属后得到 10 分钟签名 URL，iframe、下载、audio 用法无需配置 OSS CORS；Endpoint 必须能被浏览器访问。

## 已知限制与未验证项

- 不做 OCR；扫描件、损坏/加密 PDF、缺失或错误字体映射不能保证提取成功。复杂多栏 PDF 的阅读顺序仍依赖 PDFium，尚无大规模真实语料准确率评测；清理重复边缘行采用保守启发式。
- DOCX 分节按语义标题，不能据此得出物理页码；旧格式转换可能改变样式（包括标题/列表语义），无标题部分仍保留为“正文”section。PPT 图形、图表、SmartArt、图片与嵌入对象不做 OCR 或视觉理解；文本、普通表格与备注支持。
- 表格单表最多 2000 行数据；CSV 只支持 UTF-8/GBK 和上述分隔符。Office XML 总解压正文限制 20MiB；XLSX 解压预算 100MiB，正文预算 20MiB。上传上限保持 200MiB。
- 没有真实 OSS 凭据，本轮未对云端 Bucket 发请求，真实地域/网络/RAM 策略仍需部署时验证；官方 SDK 协议和签名已用本地模拟覆盖。需要公开网络播放时不能使用仅服务器可达的内网 Endpoint。
- 切换 local/oss 不自动迁移已有对象。业务删除与文件清理之间仍没有数据库事务 outbox；已持久化的失败清理可重试，数据库提交后、写入清理日志前进程崩溃仍可能需要人工清理。
- 未调用付费模型或真实 TTS。本轮引用完整链路用 Fake；MP3 存储、鉴权、Range 与 OSS 跳转通过既有及新增模拟集成测试验证，不声称真实音频解码效果。
