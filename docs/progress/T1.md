# T1 交付说明：Go 后端骨架

状态：已完成。日期：2026-11-14。

## 完成内容与关键文件

- `backend/go.mod`、`go.sum`：模块 `knownote`，Go 1.27，固定本次使用的依赖版本。
- `backend/internal/config`、`.env.example`：环境变量配置、参数校验；开发模式缺少 JWT 密钥时生成随机临时密钥并警告，生产模式强制配置至少 32 字节密钥。配置只读取进程环境，不自动读取 `.env`，符合项目密钥文件限制；可选 dotenv 加载未启用。
- `backend/internal/model`、`internal/db`：十张表、UUID 主键、时间字段、用户归属、复合外键、级联删除、JSONB、pgvector、查询索引和 HNSW 余弦索引。事务迁移通过 PostgreSQL advisory lock 串行执行，已有向量维度不匹配时明确拒绝启动。
- `backend/pkg/response`、`internal/handler/helpers.go`：统一响应、中文错误码与信息、UUID/JSON 绑定校验。JSON 请求最多 1MB，拒绝非对象、未知字段、错误类型和多余 JSON。
- `backend/internal/middleware`：slog 请求日志、Recover、按配置限制来源的 CORS、HS256 JWT。JWT 有效期 7 天，支持 Bearer 和 `?token=`；有 Authorization 时不得降级使用查询参数。日志不记录请求体、查询字符串、凭据或 SQL 参数。
- `backend/internal/service`、`internal/handler`：bcrypt 注册登录、默认用户设置、用户信息、实时存储统计、笔记本 CRUD、实时来源计数、用户隔离与删除级联。存储上限固定 5GiB（5368709120 字节），storageUsed/storageTotal 为只读，PATCH 传入时忽略。
- `backend/internal/llm`：Client 接口、可配置 BaseURL 的 OpenAI 兼容实现与自动降级的 Fake。向量化每批 64 条；兼容客户端校验结果维度与顺序，具备超时和有限重试；流式中断返回已生成部分。Fake 向量确定、归一化，中文相邻字和英文共享词提高相似度；中文回答提取输入片段，保留编号引用，逐字流式回调。
- `backend/cmd/server/main.go`：依赖组装、路由注册、启动迁移、Fake 日志提示、SIGINT/SIGTERM 优雅关闭。
- `backend/README.md`：数据库启动、配置、运行、测试和后续任务扩展说明。

未修改接口契约、前端源码、docker-compose 或其他任务文件。

## 已注册路由

所有业务路由前缀均为 `/api`，成功使用 `{code:0,data:...,message:"ok"}`，错误使用相应 HTTP 状态码和非零业务码。

| 方法 | 路径 | 鉴权 | 行为 |
|---|---|---|---|
| GET | `/api/health` | 公开 | 检测数据库，正常返回 status/db 为 ok，异常返回 503 |
| POST | `/api/auth/register` | 公开 | 注册、创建设置并签发 JWT，重复邮箱 409 |
| POST | `/api/auth/login` | 公开 | 邮箱密码登录，错误返回 401 |
| GET | `/api/me` | JWT | 当前用户，隐藏密码哈希 |
| GET | `/api/me/settings` | JWT | 用户设置与实时存储统计 |
| PATCH | `/api/me/settings` | JWT | 部分更新模型、风格和语言 |
| GET | `/api/notebooks` | JWT | 用户笔记本列表，按 updatedAt 倒序 |
| POST | `/api/notebooks` | JWT | 创建，默认标题与随机 emoji/color |
| GET | `/api/notebooks/:id` | JWT | 详情与实时 sourceCount |
| PATCH | `/api/notebooks/:id` | JWT | 部分更新，支持 color=0 和清空 description |
| DELETE | `/api/notebooks/:id` | JWT | 数据库级联删除，成功 data=null |

中间件统一处理 OPTIONS 预检；未知路径与不支持的方法返回中文统一响应。后续任务路由尚未注册。

## 表结构概要

所有表均有 UUID `id`、`created_at`、`updated_at`，由 GORM 创建时生成 UUID。以下为主要业务字段，完整定义见 `backend/internal/model/models.go`。

| 表 | 主要字段与约束 |
|---|---|
| users | 唯一 email、password_hash、nickname、avatar_url |
| user_settings | 唯一 user_id、model、answer_style、language；注册事务中创建 |
| notebooks | user_id、title、emoji、color（0～7）、description；用户/更新时间组合索引 |
| sources | user_id、notebook_id、type、title、status、progress、size、url、file_path、完整 content、summary、topics JSONB、word_count、error |
| chunks | user_id、notebook_id、source_id、chunk_index、content、token_count、embedding；source_id/chunk_index 唯一，向量为 vector(EMBEDDING_DIM) |
| messages | user_id、notebook_id、role、content、citations JSONB、可空 feedback |
| notes | user_id、notebook_id、title、content、origin |
| artifacts | user_id、notebook_id、kind、title、content、mindmap JSONB |
| audio_overviews | user_id、唯一 notebook_id、status、title、duration_sec、url、file_path、transcript、error |
| notebook_guides | user_id、唯一 notebook_id、summary、suggested_questions JSONB、stale（默认 true） |

用户删除会级联删除设置、笔记本及其子资源。笔记本的所有子资源通过 `(notebook_id,user_id)` 复合外键验证归属；分块还通过 `(source_id,notebook_id,user_id)` 验证来源归属。来源删除级联删除分块；笔记本删除级联删除所有七类子资源。各表常用归属字段和列表排序字段已有索引，chunks.embedding 建有 `vector_cosine_ops` HNSW 索引。

## T2 / T3 / T4 扩展指引

### 共用接入方式

在 `cmd/server/main.go` 构造自己的 service/handler，通过 `handler.NewRouter(s, origins, registrar...)` 注入 `func(*gin.RouterGroup)` 注册器。收到的组已包含 `/api` 前缀和 JWT 鉴权，无需再次挂载。`middleware.UserID(c)` 取得当前用户；所有资源查询继续带用户约束，跨用户资源返回 404。可复用 `handler.BindJSON`、`handler.ParamID`、`response.OK/Fail`；现有 service 通过 `service.Error` 表达业务错误。

### T2：来源、存储、分块和向量

- 使用 `Source.NotebookOwner` 设置 userID/notebookID，`Source.Content` 保存完整正文；对外 Source 预览按契约截取前 3000 字，不能将数据库完整正文直接作为预览返回。`FilePath` 只用于内部存储，禁止输出到接口。
- 写入分块用 `model.NewVector(values)`；它封装 `pgvector.Vector`，读取用 `chunk.Embedding.Slice()`。`llm.Client.Embed` 已内部按 64 条分批，结果维度与 `EMBEDDING_DIM` 一致。
- 将 `config.DataDir` 传给自己的 storage。在 `s.Files` 注入 `service.NotebookFileCleaner`，数据库删除提交后收到来源和音频路径。实现须限制路径、幂等删除并安排失败重试；可结合 userID/notebookID 清理目录以处理并发任务。T1 不删除实体文件。
- 来源新增、删除、内容处理完成时将 notebook_guides.stale 置 true，并按产品行为更新笔记本 updated_at；T1 的 sourceCount/storageUsed 实时统计，不需要维护计数字段。
- 异步处理使用可取消上下文，并在服务退出时收敛后台任务；不要让已经删除的笔记本残留任务或文件。

### T3：RAG、消息与概要

- 检索约束 user_id、notebook_id、选中 source_id 和 ready 状态，使用 embedding 的 `<=>` 余弦距离和现有 HNSW 索引。
- `model.Message.Citations` 可直接使用 `[]model.Citation`，GORM 负责 JSONB 序列化；feedback 为 `*string`，nil 表示清除反馈。
- 读取用户设置决定回答风格；将用户选择的 model 传入 `llm.ChatOptions.Model`。messages 使用 role/content，编号片段带 `[1]` 等标记即可在 Fake 回答中保留引用。
- `ChatStream` 接受请求上下文和 delta 回调；错误、客户端断开时仍返回部分文本，调用方保存已经生成的部分并决定 SSE 错误事件。
- NotebookGuide 预留 summary、suggestedQuestions 与 stale；无 ready 来源的空响应与缓存更新逻辑由 T3 实现。

### T4：笔记、产物与音频

- Note、Artifact、MindMapNode、AudioOverview 均已建表。mindmap 使用 `*model.MindMapNode` 并自动 JSONB 序列化，生成后的结构仍须在业务层校验。
- AudioOverview 每本唯一，预留 generating/ready/error 状态、脚本、时长、音频 URL、内部文件路径和错误信息；未生成时的 idle 响应由 T4 实现。
- TTS 输出 MP3 字节；未配置 TTS 模型或使用 Fake 时返回 `llm.ErrNotConfigured`，走仅脚本展示。voices 从配置读取，音频文件路由复用现有 JWT/query token 中间件并自行验证文件归属。
- Fake 当前支持中文文本和编号片段演示。T2～T4 如引入要求严格 JSON 的新提示词，需在本任务预留的 Fake 实现里补上相应离线结构化输出，确保后续完整演示。
