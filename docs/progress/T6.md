## 实际验证

环境：macOS27.2/arm64、Go1.27.1；终端Node24.21.0，npm脚本实际Node26.10.0/npm11.19.1；PostgreSQL16.16、pgvector0.8.7。原5173服务保留，本轮使用8080与5176。

- 最终 `scripts/check.sh`退出0：go build/vet、go test -count=1 -v共41个顶层测试及子用例通过，数据库集成测试实际执行、没有Skip；前端test:api与生产构建通过。
- `scripts/dev.sh`实际拉起数据库、`go run ./cmd/server`与`VITE_USE_MOCK=false npm run dev`。日志确认Fake，未读取任何密钥文件。
- 最终 `E2E_BASE_URL=http://localhost:5176 npm run test:e2e`退出0：注册→退出→登录→笔记本→PDF/公网网页/中文文本ready→概要→246次流式内容更新→引用与历史数据一致→up/down/null反馈→保存/编辑笔记→五种产物→音频文稿ready→删除来源/笔记/笔记本→退出清理状态与401。
- Chrome原生自动化补查：真实注册、XHR选择PDF并观察解析中/ready、添加网页/文本、发送中文问题、看到停止生成状态及完成回答；点击引用打开正确来源，引用框与原文高亮可见；保存笔记成功；五种产物出现在列表，思维导图节点可读；展开双主持文稿；删除PDF、删除笔记本回到零资料首页；退出回登录页。浏览器扩展主机不可用，但原生Chrome路径可用，因此历史“无法检查点击”问题已关闭。
- 性能简测：浏览器样本PDF/网页/文本后台分别41.977/236.658/16.771ms；最终脚本观测ready分别1514/1519/1527ms（含1.5秒轮询）；三分块Top-6 SQL十次执行均值0.086ms。详细口径、样本与限制见测试报告，未声称大规模性能。
