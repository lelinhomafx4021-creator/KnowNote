# T4 交付说明：笔记、工作室生成与音频概览

状态：已完成。日期：2026-11-14。

## 完成内容与关键文件

- `backend/internal/service/notes.go`、`internal/handler/studio.go`：笔记四个接口，支持 manual/chat/studio，严格校验请求字段、标题、正文与 origin；部分更新支持清空正文，列表按 updatedAt 倒序。所有笔记、产物、音频和文件请求按用户隔离，越权返回 404。
- `backend/internal/service/studio/studio.go`：产物列表、同步生成与删除；读取该笔记本全部 ready 来源的摘要、主题与代表片段。每来源按 topics 命中数、片段长度、原文位置排序取最多三块，再按原文顺序提供给模型。不加载向量、不额外调用模型评分。无 ready 来源返回 400“请先添加来源”。生成结果保存前重新锁定笔记本，避免已删除笔记本重建产物。
- `backend/internal/llm/studio.go`：五种独立中文提示词，结构对应现有前端 mock；默认标题为学习指南、简报文档、常见问题、时间线、思维导图。上下文为有效 JSON，摘要、主题、片段按来源公平分配字符预算，包含 JSON 开销最多 12000 个 Unicode 字符；不修改原始数据、不截坏汉字。极端来源数量连最小结构都放不下时明确报错。
- `backend/internal/service/studio/mindmap.go`：清除 BOM、代码围栏和 JSON 对象外说明，修复字符串之外的尾逗号；校验根为对象、根计为第 1 层且最多 4 层、每节点最多 8 个子节点、标签 1～20 字，全部节点重新补 UUID。JSON 或结构失败重试一次，两次失败返回 502“思维导图生成失败，请重试”，失败结果不入库。
- `backend/internal/service/studio/audio.go`：音频 GET/POST、双主持脚本解析、异步生成与文件归属查询。POST 在事务中置 generating 后立即返回，重复请求复用生成中的任务；单个有界 worker 以数据库记录为队列，退出取消并等待，重启恢复 generating。脚本以小知、小页分段，正文校验 1200～1800 字，格式不合格重试一次，标题为“深度对谈：<笔记本标题>”。
- 配置 TTS 时按主持人选择 `LLM_TTS_VOICES` 的前两个音色逐段调用已有 `Client.TTS`，按顺序拼接 MP3，限制总大小 64MiB。未配置 TTS 或使用 Fake 时仅提供文稿、status=ready，不伪造音频 URL；durationSec 按每秒约 4 个非空白字符估算。合成失败置 error，已经生成的 transcript 保留。
- `backend/internal/storage/audio.go`、`internal/storage/local.go`：音频通过现有 `os.Root` 保存到 `DATA_DIR/audio/<userID>/<notebookID>.mp3`，临时文件写完后原子替换。提交文件时与笔记本删除共用行锁；删除笔记本清理规范音频路径，包括重新生成失败时的旧文件；清理参数校验当前用户及笔记本归属。
- 文件 GET 复用现有 Bearer / `?token=` 鉴权，只有当前用户的 ready 音频可以访问；使用 `http.ServeContent` 支持 Range、206 与拖动进度，响应为 `audio/mpeg` 且禁止共享缓存。
- `backend/internal/llm/fake.go`：识别产物及对谈提示词；学习指南包含参考答案、FAQ 为 8 个问答、简报按来源组织、时间线仅摘取资料日期且无日期时说明；思维导图按来源 topics 构造，来源较多时分组限制深度及分支。对谈按阅读问题、概念、证据、比较、应用及总结展开，短来源和长标题均满足字数要求。
- `backend/cmd/server/main.go`：注入工作室服务和全部 T4 路由，在安全退出时收敛音频任务。

## 已知限制与未验证项

- 未调用真实付费模型或 TTS；真实 curl 验收使用 Fake，语音片段拼接、文件鉴权和 Range 使用模拟合成字节的数据库集成测试验证，未验证浏览器对真实 MP3 的解码/拖动效果。
- durationSec 是文字速率估计，未解析 MP3 帧时长；MP3 按任务要求直接顺序拼接，不做转码。
- 来源片段代表性按主题命中等启发式选择，Fake 是基于摘要/片段的离线整理，不替代真实模型的综合分析；思维导图离线构造最多覆盖 64 个来源分支，单来源最多 8 个主题。
- 音频队列与 T2 来源队列一样面向单进程部署，未实现多实例抢占。关机保留 generating 供重启恢复；错误任务由用户再次 POST 重新生成。
