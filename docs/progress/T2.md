## 完成内容与关键文件

- `backend/internal/handler/sources.go`、`internal/service/sources.go`：来源全部六个接口，复用 T1 鉴权、参数校验和统一响应。列表按创建时间正序，所有业务读写按当前用户隔离，跨用户访问返回 404。响应使用独立 `SourceView`，仅输出契约字段，正文预览按 Unicode 字符截取前 3000 字，数据库保留完整清洗正文。
- `backend/internal/storage/local.go`：上传文件保存到 `DATA_DIR/uploads/<userID>/<sourceID>/<原文件名>`，数据库保存相对于 DATA_DIR 的路径与实际文件字节数。文件严格限制 200MiB，扩展名不区分大小写，旧版 `.doc` 返回转换为 DOCX/PDF 的中文提示。用 `os.Root` 限定文件访问范围，校验 UUID 与文件名，禁止目录穿越和越界符号链接。删除来源清理整个来源目录，删除笔记本复用 T1 文件清理钩子；失败清理写入 `.cleanup/` 日志，每 5 秒重试，重启恢复。
- `backend/internal/parser`：PDF 使用指定的 `ledongthuc/pdf` 逐页提取，跳过空页，清理替代符；没有有效文字时返回“未能从 PDF 中提取文字，可能是扫描件”。DOCX 在压缩包内读取 `word/document.xml`，拼接文本 run，保留段落、换行和制表。Markdown/TXT 支持 UTF-8、BOM 与 GBK。清洗合并行内空白与连续空行，删除控制字符，保留段落边界。
- `backend/internal/parser/web.go`：20 秒超时、10MiB 响应限制、浏览器 UA，使用指定的 `go-readability` 提取正文和标题；没有自定义标题时采用网页标题。校验初始地址和重定向，解析 DNS 后直接连接已校验的公网 IP，限制内网地址及重定向次数。网页字符集按 HTTP/HTML 信息解码。
- 音频、YouTube 与 B 站链接不请求转写服务，正文为“（暂不支持自动转写，可粘贴字幕文本作为来源）”，仍完成切分和向量化并进入 ready；摘要明确说明尚未分析真实音视频，建议另建字幕文本来源。
- `backend/internal/rag/chunker.go`：目标 500 字，精确保留 80 字上下文；在后半段优先选择段落或句末，短段自然合并，超长句按字符截断，少于 100 字的尾段并入前块，单块最多 599 字。
- `backend/internal/llm/source_summary.go`、`fake.go`：摘要提示词要求 JSON，校验 120～200 字中文摘要和 3～6 个去重主题；JSON/结构校验失败降级为中文原文摘录与词频关键词。Fake 复用该确定性降级算法输出合规 JSON，原有聊天行为保持兼容。
- `backend/internal/rag/retriever.go`：给 T3 使用的 pgvector 余弦 Top-K 检索器，复用 T1 的向量列和 HNSW 索引。
- `backend/internal/service/notebooks.go`、`cmd/server/main.go`：注入来源路由、存储、队列与清理器；笔记本删除前锁定笔记本行，协调并发上传；退出时取消并等待后台任务。存储统计继续复用 T1 的 `SUM(sources.size)`，上传写入真实大小后即可统计，删除后立即扣除。

## 后台流水线与一致性

1. 上传/创建时验证笔记本归属，在事务中写入 processing 来源，并使 `notebook_guides.stale=true`、刷新笔记本更新时间；接口立即返回 processing。
2. `internal/service/ingest` 使用数据库 processing 记录作为持久队列，单进程固定 3 个 worker。创建后通知调度器，另每 2 秒扫描；启动时自动恢复所有未完成来源，内存不堆积全部正文或任务。
3. worker 依次执行解析 → 清洗 → 字符切分 → 调用现有 `llm.Client.Embed` → 校验返回数量/维度 → 事务替换该来源 chunks → 调用 LLM 生成摘要与主题 → 事务更新完整正文、summary、topics、wordCount、progress=100、status=ready，并再次使概要缓存失效。
4. `Embed` 内部分批仍复用 T1 的每批 64 条实现。分块写入也每批 64 条，失败时整次分块事务回滚；已写分块在来源 ready 前不会被 Retriever 读取。恢复任务先替换旧分块，避免重复。
5. 单次处理预算 10 分钟。解析、向量化、摘要调用或数据库操作失败时记录中文 error 并置为 error；摘要 JSON 无效是明确的降级例外。关闭服务导致的取消保留 processing，供下次恢复。
6. 上传、来源删除、笔记本删除和 worker 提交统一先锁笔记本行，再操作来源。worker 提交前重新确认来源仍存在且为 processing，处理中删除不会重建来源、分块或文件；网页完成时读取当前标题，保留用户处理中所做的重命名。
7. `wordCount` 和分块 `tokenCount` 使用非空白 Unicode 字符数，包含标点；后者是字符估算值，不代表模型 tokenizer 的精确 token 数。原文预览的 3000 字限制则包含空白。

## Retriever 用法（T3）

```go
retriever := rag.NewRetriever(database)
vectors, err := client.Embed(ctx, []string{question})
if err != nil {
    return err
}
chunks, err := retriever.Search(ctx, userID, notebookID, sourceIDs, vectors[0], 6)
```

- 签名：`Search(ctx, userID, notebookID string, sourceIDs []string, queryVec []float32, topK int) ([]ScoredChunk, error)`。
- 查询同时约束 chunks/sources 的 user_id、notebook_id、选中 source_id，并要求来源 status=ready；按 `embedding <=> queryVec` 升序排序。
- `ScoredChunk` 返回 `ChunkID`、`SourceID`、`SourceTitle`、`Content`、`ChunkIndex`、`Score`；Score 为 `1 - 余弦距离`，越大越相似。
- `topK<=0` 默认 6，上限 100；空 sourceIDs 直接返回非 nil 空数组，不查询数据库。T3 应先处理“请选择来源”，避免此时调用 Embed，并自行按契约校验笔记本。
- 空向量、零向量、非有限值返回中文错误；向量维度应与当前模型/数据库配置一致。
- T3 概要生成若需和来源更新串行协调，应在保存缓存前锁定同一笔记本行并重新检查 stale/来源状态。

## 已知限制与未验证项

- 不做 OCR、旧 DOC 转换或音视频转写；扫描 PDF 需要先 OCR，音视频需粘贴字幕文本。网页抓取不执行 JavaScript，不支持需登录或反爬验证的页面，也不允许访问本地/内网网页。
- 上传上限 200MiB；为限制解析内存，TXT/Markdown 和 DOCX 解压正文、PDF 提取正文另限制 20MiB，网页响应限制 10MiB。
- 指定的 `github.com/go-shiori/go-readability` 已被上游标记弃用，本任务按要求固定使用该包；未擅自替换任务指定依赖。
- 实际验收使用 Fake；未调用付费模型。摘要输入取前 12000 字，Fake/降级摘要为原文摘录、主题为简单词频，不能替代真实模型的综合分析。
- 队列面向当前单服务进程，未实现多实例分布式抢占；error 来源不会自动重新尝试，需删除后重新添加。进程关闭时 processing 可恢复；清理日志仅覆盖已安排的清理任务，尚无跨数据库/文件系统的事务型 outbox。
