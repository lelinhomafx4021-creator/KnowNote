【KnowNote T11】管理员后台（精简版）：在平台内更换模型密钥、管理用户

你是 KnowNote 项目的全栈工程师，负责任务 T11。先完整阅读 `AGENTS.md`、`docs/api.md`、`docs/数据库设计.md`、`docs/progress/` 下全部交付说明（尤其 T7、T9、T10），以及 `backend/internal/config`、`internal/llm`（含 usage/Guard）、`internal/db/reindex.go`、`scripts/dev.sh`。可修改 `backend/`、`frontend/`、`docs/`、`scripts/dev.sh`。

## 背景
系统给很多人用，所有人共用服务端的 DeepSeek（对话）与阿里百炼（向量）密钥。目前密钥与模型只能改 `backend/.env` 并重启。本任务做一个**精简**的管理员后台，只解决两件事：
1. 管理员在网页上更换对话/向量模型的密钥、地址、模型名与每日额度，**保存后立即生效，不用重启**；
2. 管理员能看到每个用户的用量，并能禁用滥用的账号。

**不要做**：OSS 存储配置界面、TTS/图像配置界面、复杂图表、多实例同步。保持代码简洁。

## 必须完成
1. **角色与禁用**：
   - `users` 增加 `role`（`user` | `admin`，默认 `user`）与 `disabled`（bool，默认 false）。
   - 管理员认定：环境变量 `ADMIN_EMAILS`（逗号分隔）中的邮箱在注册/登录/启动时被设为管理员；若数据库中**没有任何管理员**且未配置 `ADMIN_EMAILS`，则最早注册的用户成为管理员。
   - 管理员中间件**每次从数据库读取**当前用户的 role/disabled（不要只信 JWT），这样禁用和撤销管理员立即生效。被禁用的用户登录返回 403“账号已被停用”，已有 token 的请求也返回 403。
   - 不能禁用自己、不能撤销自己的管理员、不能让系统没有管理员。
   - `GET /api/me` 返回值增加 `role`。
2. **系统配置表** `system_settings`（key PK、value text、is_secret bool、updated_by FK→users ON DELETE SET NULL、updated_at）。可在后台修改的项**只有**：
   - 对话：`CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL`、`CHAT_MODELS`
   - 向量：`EMBED_BASE_URL`、`EMBED_API_KEY`、`EMBED_MODEL`
   - 额度：`QUOTA_DAILY_CHAT_REQUESTS`、`QUOTA_DAILY_TOKENS`
   读取优先级：数据库值 > `.env`/环境变量 > 内置默认。`EMBEDDING_DIM` 不可在后台改（由数据库列决定）。
3. **密钥加密与掩码**：`*_API_KEY` 用 AES-GCM 加密后存库，主密钥取 `SETTINGS_ENCRYPTION_KEY`，未设置时由 `JWT_SECRET` 用 SHA-256 派生。解密失败（例如主密钥变了）时记录警告并回退到环境变量值，不能崩溃。接口**永远不返回明文**，只返回 `sk-****e12a` 形式的掩码（前 3 + 后 4）；提交空字符串表示“不修改”，提交特殊值 `__CLEAR__` 表示删除数据库值、回退到环境变量。日志里也不能出现明文。
4. **热更新**（核心）：
   - 在 `internal/llm` 增加一个持有当前客户端的 `Provider`（用 `atomic.Pointer` 或读写锁），对话、摘要、工作室、向量化、问答等所有调用点改为每次从 `Provider` 取当前客户端，而不是启动时固定的全局实例；额度 Guard 也每次读取当前额度配置。
   - 管理员保存配置时：先用新配置构造客户端并**测试连接**（对话发一条极短消息；向量嵌入一条短文本并校验返回维度 = `EMBEDDING_DIM`）。测试失败则**不保存**，返回中文错误（不得包含密钥或上游原始响应中的敏感信息）。测试通过则写库 → 原子替换客户端。正在进行的流式回答继续用旧客户端完成，不中断。
   - 如果 `EMBED_MODEL` 或 `EMBED_BASE_URL` 发生变化，保存成功后在返回值与界面中提示“向量模型已更换，旧资料需要重建向量才能被准确检索”，并提供“重建全部向量”按钮：后台异步执行（复用 T9 的重建逻辑），`GET /api/admin/reindex` 返回进度（总数/已完成/失败/是否运行中），同一时间只允许一个重建任务。
5. **接口**（全部在 `/api/admin/` 下，非管理员 403；写入 `docs/api.md`）：
   - `GET /api/admin/settings`：分组（对话 / 向量 / 额度）返回每项的当前值（密钥打码）与来源（`database` / `env` / `default`）。
   - `PATCH /api/admin/settings`：部分更新，按上面的规则测试并热更新。
   - `POST /api/admin/settings/test`：只测试不保存（body 同 PATCH，可只测对话或只测向量），返回 `{ ok, latencyMs, message }`。
   - `GET /api/admin/users?query=`：用户列表（邮箱、昵称、角色、是否停用、注册时间、笔记本数、今日请求数、今日 tokens、近 7 天 tokens），分页。
   - `PATCH /api/admin/users/:id`：`{ disabled?, role? }`。
   - `GET /api/admin/usage`：近 7 天每日总请求数与 tokens，以及今日用量前 10 的用户。
   - `POST /api/admin/reindex`、`GET /api/admin/reindex`。
6. **审计**：表 `audit_logs`（id、user_id FK→users ON DELETE SET NULL、action、target、detail 已脱敏、created_at）。修改配置、禁用/启用用户、变更角色、启动重建时写入。`GET /api/admin/audit-logs` 返回最近 50 条。
7. **前端** `/admin`（仅管理员可见，用户头像菜单增加“管理后台”入口；非管理员访问时跳回首页并提示）：
   - 风格与现有 NotebookLM / Material 3 页面一致，中文；左侧导航四项：**模型与密钥**、**用户管理**、**用量**、**操作记录**。移动端改为顶部选项卡。
   - 模型与密钥：对话、向量两张卡片，字段显示来源小标签（数据库 / 环境变量 / 默认）；密钥输入框显示掩码占位，留空不修改，有“清除，改用环境变量”的操作；“测试连接”和“保存”按钮，保存时显示测试中状态；向量模型变更后显示重建提示与进度条。额度卡片：两个数字输入（0 表示不限）。
   - 用户管理：搜索框 + 表格（移动端卡片），可停用/启用、设为/取消管理员（带确认弹窗）。
   - 用量：近 7 天的简单柱状图（纯 CSS 或 SVG，不引入图表库）+ 今日 Top 10 表格。
   - 操作记录：列表。
   - mock 模式同步支持（mock 用户为管理员）。
8. **启动脚本**：`scripts/dev.sh` 的读取白名单加入 `ADMIN_EMAILS` 与 `SETTINGS_ENCRYPTION_KEY`；`backend/.env.example` 增加这两项说明（值留空）。
9. **文档**：`docs/数据库设计.md` 补充 users.role/disabled、system_settings、audit_logs（E-R 图、关系说明表、数据字典、索引清单）；`docs/架构设计.md` 增加一小节“配置热更新”（数据库优先的读取顺序、Provider 原子替换、先测试后生效、向量更换需重建、多实例部署时的扩展思路一两句即可）。
10. **测试**：配置优先级、加解密与掩码（含主密钥变化时回退）、空值不修改与 `__CLEAR__`、测试失败不保存、保存后新请求使用新客户端而进行中的流不受影响、管理员鉴权与普通用户 403、停用用户 403、不能禁用自己/最后一个管理员、审计写入且不含明文。外部服务一律用 `httptest` 模拟。

## 验证（必须实际执行并通过）
- **不要影响用户正在使用的演示系统**：8080（后端）与 5174（前端）保持运行，不要停止。
- **必须使用独立数据库验证**：在同一个容器里创建库 `knownote_t11`（`docker exec knownote-postgres psql -U knownote -d knownote -c "CREATE DATABASE knownote_t11"`，并在新库中 `CREATE EXTENSION vector`），验证后端用 `DATABASE_URL=postgres://knownote:knownote@localhost:5432/knownote_t11?sslmode=disable PORT=18090 CORS_ORIGINS=http://localhost:5190`，前端用 `VITE_USE_MOCK=false VITE_API_BASE_URL=http://localhost:18090/api npx vite --port 5190`。**绝不能把 system_settings 写进主库 knownote**，否则会改掉用户正在使用的真实模型配置。集成测试若需要数据库，同样指向独立库或在事务中回滚。验证结束后 `DROP DATABASE knownote_t11`。
- 不读取、不修改 `backend/.env`；不配置任何真实密钥，对话与向量都用 `httptest` 或本地 Go 小程序起的模拟服务（可起两个不同端口的模拟服务 A、B 来演示切换）。
