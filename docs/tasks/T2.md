## 目标
实现 api.md 中“来源”部分的全部接口与后台处理流水线。

## 必须完成
1. **存储** `internal/storage`：本地文件存储在 `DATA_DIR/uploads/<userID>/<sourceID>/<原文件名>`；提供删除笔记本 / 来源时清理文件的方法，并接入 T1 预留的笔记本级联删除。
2. **接口**：
   - `POST /api/notebooks/:id/sources/upload`（multipart `file`，≤200MB，按扩展名判定 type：pdf/docx(含 doc 时返回不支持的友好错误)/markdown/text/audio）
   - `POST /api/notebooks/:id/sources`（web / youtube / text）
   - `GET /api/notebooks/:id/sources`、`GET/PATCH/DELETE /api/sources/:id`
   返回字段严格按 api.md 的 Source；`content` 只返回原文前 3000 字。
3. **解析** `internal/parser`：
   - PDF：github.com/ledongthuc/pdf 提取文本（处理乱码/空页，提取不到文字时 status=error，error="未能从 PDF 中提取文字，可能是扫描件"）。
   - DOCX：解压读取 `word/document.xml`，按段落提取。
   - Markdown / TXT：直接读取，自动处理 UTF-8 / GBK。
   - 网页：HTTP 抓取（超时 20s、限制 10MB、带浏览器 UA）+ github.com/go-shiori/go-readability 提取正文与标题（title 为空时用网页标题）。
   - YouTube / B 站链接与音频文件：本期不做转写，生成占位正文“（暂不支持自动转写，可粘贴字幕文本作为来源）”并 status=ready，summary 说明情况；保证流程不报错。
   - 文本清洗：合并多余空白、去除控制字符。
4. **切分** `internal/rag/chunker.go`：按段落/句子边界切分，目标约 500 字、重叠 80 字，过短段落合并；中文按字符计数。写充分的单元测试（边界、重叠、超长句、空文本）。
5. **处理流水线** `internal/service/ingest`：上传/创建后立即返回 status=processing，后台 goroutine（带并发上限，如 3 个 worker 的队列）依次：解析 → 清洗 → 切分 → `llm.Embed` 批量向量化 → 事务写入 chunks → 用 LLM 生成 summary（120~200 字中文）与 3~6 个 topics（要求模型返回 JSON，解析失败时降级为从文本提取关键词）→ 更新 wordCount、status=ready。任何一步失败：status=error 并记录 error。服务重启时把卡在 processing 的来源重新入队。来源变化后把该笔记本的 notebook_guides 标记为 stale。
6. **向量检索工具**（给 T3 用）`internal/rag/retriever.go`：`Search(ctx, userID, notebookID string, sourceIDs []string, queryVec []float32, topK int) ([]ScoredChunk, error)`，用 pgvector 余弦距离 `<=>`，只查 status=ready 的来源，返回 chunk 内容、来源标题、相似度。写集成测试（Fake LLM 向量，DB 不可用时 Skip）。
7. **storageUsed** 统计确保包含新上传文件大小。
