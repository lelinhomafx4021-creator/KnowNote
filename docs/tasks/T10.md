你是 KnowNote 项目的全栈工程师，负责任务 T10。先完整阅读 `AGENTS.md`、`docs/api.md`、`docs/架构设计.md`（现有 ER 图）、`docs/progress/` 下全部交付说明，以及 `backend/internal/model`、`db`、`service/chat`、前端首页与笔记本卡片。可修改 `backend/`、`frontend/`、`docs/`。

## 背景
这是毕业设计，论文需要一张关系清晰的 E-R 图。目前所有表都以“用户 1:N 笔记本 1:N 各类数据”的星形挂在 notebooks 下，缺少多对多关系，消息引用也只存成 jsonb，ER 图里体现不出来。本任务**少量**补充实体与关系，让 ER 图同时包含 1:1、1:N、M:N，并输出论文可直接使用的数据库设计文档。保持现有接口兼容，前端界面风格沿用 NotebookLM / Material 3。

## 必须完成
1. **标签（M:N）**：
   - 表 `tags`（id、user_id FK→users、name、color、created_at；同一用户下 name 唯一）与关联表 `notebook_tags`（notebook_id FK、tag_id FK，联合主键，均 ON DELETE CASCADE）。
   - 接口：`GET/POST /api/tags`、`PATCH/DELETE /api/tags/:id`、`PUT /api/notebooks/:id/tags`（body `{ tagIds }` 整体替换）；`Notebook` 返回值增加 `tags: Tag[]`；`GET /api/notebooks?tag=<id>` 按标签过滤。写入 `docs/api.md`。
   - 前端：笔记本卡片底部显示标签小圆角徽标；卡片“更多”菜单增加“编辑标签”（弹窗内勾选已有标签、新建标签、选颜色）；首页工具条增加标签筛选（胶囊按钮组）。mock 模式同步支持。
2. **消息引用表（M:N）**：新建 `message_citations`（id、message_id FK→messages、chunk_id FK→chunks ON DELETE SET NULL、source_id FK→sources ON DELETE SET NULL、index、quote、page、location_label），chat 保存回答时写入此表；读取消息时从此表组装 citations（接口返回格式不变）。写一次性迁移：把已有 `messages.citations` jsonb 数据搬到新表，之后 jsonb 列保留但不再写入（在文档里说明）。这样 ER 图里体现“消息 —引用— 分块/来源”的多对多关系。
3. **登录日志（1:N）**：表 `login_logs`（id、user_id FK→users 可空、email、success、ip、user_agent、created_at）。登录/注册成功与失败都记录（失败时 user_id 为空，记录尝试的 email）；同一邮箱 10 分钟内失败 ≥5 次时返回 429“尝试次数过多，请稍后再试”。新增 `GET /api/me/login-logs`（最近 20 条），前端设置弹窗增加“登录记录”小节。
4. **约束检查**：确认所有外键都有索引、删除策略合理（CASCADE / SET NULL），给常用查询补复合索引；在测试里断言删除用户/笔记本后关联数据被正确级联。
5. **数据库设计文档** `docs/数据库设计.md`（供以后写毕业论文时取材，参见 `docs/论文/论文写作指南.md` 第四节图表清单）：
   - 总体 E-R 图（Mermaid `erDiagram`，中文关系名，标明 1:1 / 1:N / M:N 基数，包含全部表）；
   - 实体关系说明表：每条关系的两端实体、基数、外键、删除策略、业务含义；
   - 数据字典：每张表一张表格（字段名、类型、长度/精度、是否可空、默认值、键（PK/FK/UK）、说明），中文说明；
   - 索引清单（含 HNSW 向量索引说明）；
   - 同步更新 `docs/架构设计.md` 里的 ER 图与之一致（或改为引用新文档）。
6. **测试**：标签 CRUD 与过滤、标签权限隔离、引用表写入与迁移、登录失败限流、级联删除。
