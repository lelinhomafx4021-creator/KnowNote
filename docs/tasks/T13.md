【KnowNote T13】工作室生成文件：演示文稿（PPTX）与 PDF 报告

你是 KnowNote 项目的全栈工程师，负责任务 T13。先完整阅读 `AGENTS.md`、`docs/api.md`、`docs/数据库设计.md`、`docs/progress/` 下全部交付说明（尤其 T4、T7、T9、T11、T12），以及 `backend/internal/service/studio`、`internal/parser`（pptx 解析、LibreOffice 转换与中文字体 `linkCJKFonts`、go-pdfium）、`internal/storage`、前端 `features/studio`。可修改 `backend/`、`frontend/`、`docs/`。

## 背景
右侧“工作室”现在能一键生成学习指南、简报、FAQ、时间线、思维导图，但都是页面里的 Markdown 文本。用户希望工作室能**产出真正的文件**：根据笔记本资料生成一份 **PPT 演示文稿（.pptx）** 和一份 **PDF 报告**，在界面上与普通文本生成分开展示，可在线预览、可下载，拿去答辩或分享。

**用户偏好**：对模型输出不要设太多硬性限制（页数、字数都只作为“建议”写进提示词，解析时宽松容错，能用就用），不要因为格式小问题让生成失败。

## 必须完成
1. **两种新生成类型**（`StudioKind` 增加 `slides`、`report`）：
   - 生成参数（可选）：`{ topic?: 重点/主题, audience?: 听众（如答辩评委、同学、自学）, length?: 'short'|'medium'|'long'（建议页数：PPT 约 6/10/15 页，报告约 3/6/10 页）, theme?: 主题配色 }`。
   - 生成较慢，改为**异步**：创建后 `status=generating`，后台完成后 `ready`，失败 `failed` + 中文错误；前端轮询（复用现有轮询模式）。同一笔记本同时只允许一个文件类生成任务。旧的文本类型保持同步行为不变。
   - 内容依据笔记本来源（复用工作室现有的上下文构建），要点后保留来源引用：PPT 每页备注里列出“参考：来源标题 第N页/第N张”；PDF 报告正文用 [n] 标注并在文末“参考来源”列出来源标题与位置。
2. **演示文稿 PPTX**：
   - 模型输出 JSON 大纲：`{ title, subtitle, slides: [{ layout: 'title'|'section'|'bullets'|'two-column'|'quote'|'summary', title, bullets[], left[], right[], quote, notes, refs[] }] }`；解析宽松（未知 layout 当 bullets、缺字段跳过、过长文本自动缩小字号或分页）。
   - 后端用 Go 直接生成合法的 OOXML `.pptx`（`go:embed` 模板 + `archive/zip`，16:9；不引入付费库），中文字体设置 `ea` 字体（如“PingFang SC / Microsoft YaHei / Noto Sans CJK SC”回退），至少 3 套主题配色（与站点 Material 3 风格协调，例如：蓝色学术、深色简约、暖色活力）。标题页、章节页、要点页、双栏页、引用页、总结页版式都要像样：留白、层级、对齐，不能是纯文字堆砌。
   - 生成后用 LibreOffice 转 PDF（复用 `parser.Convert` 与中文字体处理），再用 go-pdfium 把每页渲染成 PNG 作为**预览图**（宽 1280 左右）。没有 LibreOffice 时仍要能生成和下载 .pptx，预览退化为前端根据 JSON 大纲用 HTML 渲染的幻灯片。
   - 必须能被 PowerPoint / Keynote / WPS 正常打开（结构符合规范：`[Content_Types].xml`、`_rels`、`presentation.xml`、slideMaster/slideLayout/theme、每页 slide 及其 rels、notesSlide）。
3. **PDF 报告**：
   - 模型输出结构化 Markdown（标题、摘要、多级章节、列表、表格、[n] 引用）。后端渲染为带样式的 HTML（封面：标题、副标题、笔记本名、生成日期；目录；正文；参考来源），再用 LibreOffice 转 PDF（中文字体必须正常显示），并用 go-pdfium 渲染每页 PNG 作为预览图。
   - 另外给已有的文本生成（学习指南、简报、FAQ、时间线）和笔记增加“导出 PDF”按钮，复用同一套渲染（同步生成即可，或复用异步任务，自行选择更简单可靠的做法）。
4. **存储与接口**（写入 `docs/api.md`）：
   - 文件存到存储层（兼容 local / OSS）：`<prefix>artifacts/<userID>/<artifactID>/deck.pptx | report.pdf | preview.pdf | pages/<n>.png`。删除生成物时一并删除文件。
   - `artifacts` 表增加 `status`、`error`、`options`（jsonb）、`outline`（jsonb，PPT 大纲）、`page_count`、`files`（jsonb：各文件的 key、大小、类型）等必要字段；`docs/数据库设计.md` 同步。
   - `POST /notebooks/:id/artifacts` 支持 `{ kind, options }`；`GET /artifacts/:id`（轮询用）；`GET /artifacts/:id/file?format=pptx|pdf`（下载，带中文文件名，鉴权方式与 T4 的来源原件下载一致，OSS 时可 302 到签名地址）；`GET /artifacts/:id/pages/:n`（预览图）；`POST /artifacts/:id/export-pdf` 或等价接口（文本生成/笔记导出 PDF）。
   - 计入调用用量与额度（T9 Guard），模型地址/密钥走 T11 的 Provider 热更新。
5. **前端（与普通文本生成分开）**：
   - 工作室面板在“一键生成”下方新增独立分区 **“生成文件”**：两张较大的卡片「演示文稿 PPT」「PDF 报告」，带文件类型图标与说明。点击打开参数弹窗（重点、听众、篇幅、主题配色色块选择），确认后开始生成，卡片显示进度/生成中状态。
   - 列表里文件类生成物显示文件类型徽标（PPTX / PDF）、页数、生成时间，失败可重试。
   - **幻灯片查看器**：大图 + 底部缩略图条，左右方向键翻页，“放映”全屏模式，显示当前页备注与引用；顶部“下载 PPTX”“下载 PDF”。
   - **PDF 查看器**：按页显示预览图（懒加载），页码跳转，下载 PDF。两种查看器都**不依赖浏览器自带 PDF 插件**。
   - 文本生成物和笔记的详情里增加“导出 PDF”。
   - mock 模式同步支持（用 HTML 渲染的示例幻灯片与示例报告页，下载可给一个小的示例文件或提示 mock 不可下载）。
   - 移动端（375 宽）可用。
6. **Fake 模型**：Fake 也要返回结构完整的 PPT 大纲 JSON 和报告 Markdown（基于来源标题、主题），使无密钥时全流程可演示。
7. **测试**：大纲 JSON 宽松解析、PPTX 结构合法（解压后各 XML 可解析、页数与大纲一致、中文文本存在、备注页存在）、有 LibreOffice 时 PPTX→PDF→PNG 页数一致且 PDF 能提取到中文（无 LibreOffice 时 `t.Skip`）、报告 PDF 含中文与参考来源、异步状态流转与失败重试、删除清理文件、用户隔离 404、下载鉴权。
