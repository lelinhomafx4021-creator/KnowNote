【KnowNote T4】笔记与工作室：笔记 CRUD、五种内容生成、音频概览

你是 KnowNote 项目的后端工程师，负责任务 T4。先完整阅读 `AGENTS.md`、`docs/api.md`、`docs/开发计划.md` 与 `docs/progress/` 下全部交付说明，复用已有模块。只改 `backend/` 和 `docs/`。

## 必须完成
1. **笔记**：`GET/POST /api/notebooks/:id/notes`、`PATCH/DELETE /api/notes/:id`，origin 校验，updatedAt 倒序。
2. **工作室产物**：`GET/POST /api/notebooks/:id/artifacts`、`DELETE /api/artifacts/:id`。
   - 上下文：取该笔记本所有 ready 来源的 summary + 每个来源最具代表性的若干 chunk（控制总长度，如 ≤12000 字）。无 ready 来源返回 400“请先添加来源”。
   - 五种 kind 各自的提示词（中文 Markdown，结构对齐前端 mock 的效果）：
     - study-guide：学习目标、简答题（附参考答案要点）、论述题、术语表
     - briefing：执行摘要、核心主题（分来源）、关键结论与建议
     - faq：6~10 个问答，`### 问题` + 回答
     - timeline：时间线表格（时间 | 事件）+ 人物表；资料没有时间信息时说明
     - mindmap：要求模型输出 JSON `{label, children:[...]}`，后端校验（深度≤4、每层≤8、label≤20 字）、补 id、修复常见格式问题（去 ```json 包裹等），失败重试一次，仍失败返回 502“思维导图生成失败，请重试”。
   - 标题默认为 学习指南/简报文档/常见问题/时间线/思维导图。
3. **音频概览**：`GET/POST /api/notebooks/:id/audio`、`GET /api/files/audio/:file`（鉴权，支持 `?token=`，校验文件归属，支持 Range 以便拖动进度）。
   - POST：状态置 generating 并立即返回；后台生成两位主持人（“小知”“小页”）约 1200~1800 字的中文对谈脚本存入 transcript，标题“深度对谈：<笔记本标题>”。
   - 配置了 `LLM_TTS_MODEL` 时按说话人分段调用 TTS（两个音色来自 LLM_TTS_VOICES），把 mp3 片段顺序拼接写入 `DATA_DIR/audio/<userID>/<notebookID>.mp3`，估算/计算 durationSec，给出 url `/api/files/audio/<notebookID>.mp3`；未配置时 status=ready 只有 transcript（durationSec 按字数估算）。失败 status=error。
4. **Fake 模型适配**：不配密钥时五种产物、思维导图 JSON、对谈脚本都能生成合理内容（思维导图根据来源 topics 构造）。
5. **测试**：mindmap JSON 清洗/校验、上下文截断的单元测试；notes 与 artifacts 集成测试（DB 不可用时 Skip）。
