【KnowNote T9】多模型接入：DeepSeek 对话 + 阿里百炼向量模型，预留图像生成

你是 KnowNote 项目的全栈工程师，负责任务 T9。先完整阅读 `AGENTS.md`、`docs/api.md`、`docs/开发计划.md`、`docs/progress/` 下全部交付说明（尤其 T1、T6、T7），以及 `backend/internal/llm`、`backend/internal/config`、`scripts/dev.sh`、前端设置弹窗。可修改 `backend/`、`frontend/`、`scripts/`、`docs/`。

## 背景
目前 `internal/llm` 的对话、向量化、TTS 共用一个 `LLM_BASE_URL` + `LLM_API_KEY`，无法“DeepSeek 负责对话、阿里云百炼负责向量化”。本任务把各能力拆成独立的提供方配置，并为以后接入图像生成模型预留扩展点。**绝不读取或打印任何真实密钥**；没有密钥时所有功能必须照常用 Fake 跑通。

## 必须完成
1. **按能力拆分配置**（`internal/config`，旧的 `LLM_*` 作为所有能力的回退值，保持向后兼容）：
   - 对话：`CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL`、`CHAT_MODELS`（可选，逗号分隔的可选模型列表，供前端设置里切换）
   - 向量：`EMBED_BASE_URL`、`EMBED_API_KEY`、`EMBED_MODEL`、`EMBEDDING_DIM`
   - 语音：`TTS_BASE_URL`、`TTS_API_KEY`、`TTS_MODEL`、`TTS_VOICES`
   - 图像（预留）：`IMAGE_PROVIDER`（`openai` | `dashscope` | 空=关闭）、`IMAGE_BASE_URL`、`IMAGE_API_KEY`、`IMAGE_MODEL`
   每个能力独立判断用真实实现还是 Fake（例如只配了向量没配对话，就对话 Fake、向量真实），启动日志逐项打印“能力 / 提供方域名 / 模型 / 真实或 Fake”，不打印密钥。
2. **DeepSeek 对话适配**：已确认 base_url 为 `https://api.deepseek.com`，当前账号可用模型为 `deepseek-flash`（默认）与 `deepseek-v4-pro`（可再查官方文档补充说明二者区别，写入 `.env.example` 注释与 README）；流式输出时忽略推理模型返回的 `reasoning_content`，只把正式回答发给前端；需要 JSON 输出的场景（摘要主题、思维导图、概要）优先用 `response_format: json_object`，不支持时回退到现有的文本 JSON 解析。
3. **阿里百炼向量适配**：查阅阿里云百炼官方文档确认 OpenAI 兼容模式的 base_url、当前推荐的文本向量模型（如 text-embedding-v4）及其支持的 `dimensions` 取值和单批条数上限；请求时传 `dimensions=EMBEDDING_DIM`；启动时（配置了真实向量服务时）用一条短文本探测返回维度，与 `EMBEDDING_DIM` 及数据库 `chunks.embedding` 列维度不一致时给出清晰的中文错误与处理办法（如何重建向量）。新增 `scripts/reindex.sh`（或后端子命令）：在更换向量模型/维度后重建所有来源的向量。
4. **模型列表接口**：新增 `GET /api/models` → `{ chat: [{ id, name, provider }], embed: { model, dimension, provider }, tts: { enabled }, image: { enabled, provider, model } }`，同步写入 `docs/api.md`。`PATCH /me/settings` 校验 `model` 必须在 chat 列表内。前端设置弹窗的“对话模型”改为读取这个接口（mock 模式保留现有演示列表），选中值保存到用户设置并在对话时使用。
5. **图像生成扩展点（只做后端接口与配置，不做界面）**：在 `internal/llm` 定义 `ImageClient` 接口 `Generate(ctx, prompt string, opts ImageOptions) (ImageResult, error)`；实现 OpenAI 兼容 `/images/generations`（返回 b64 或 url 都要处理）与 Fake（生成一张带提示词文字的简单 PNG）；结果通过存储层保存（兼容 T7 的 local / OSS）。暂不暴露业务接口，只在 `docs/架构设计.md` 写清楚以后如何接入（例如工作室里“生成封面/信息图”）。
6. **多人共用一个密钥的保护**（系统会给很多人使用，所有人共用服务端的同一个 API Key）：
   - 每次调用模型（对话、摘要、工作室生成、向量化）记录用量：新表 `llm_usage`（user_id、能力、模型、prompt/completion tokens、耗时、成功与否、created_at），流式回答从最终 usage 字段或按字数估算。
   - 每用户每日额度：`QUOTA_DAILY_CHAT_REQUESTS`（默认 200）、`QUOTA_DAILY_TOKENS`（默认 200000），超出返回 429“今日额度已用完，明天再来”；SSE 场景以 error 事件提示。额度为 0 表示不限。
   - 全局并发上限 `LLM_MAX_CONCURRENCY`（默认 8）与对每个用户的简单限速（如每分钟 20 次提问），防止个别用户刷爆。
   - 遇到上游 429/5xx 时有限重试并给出友好中文错误，绝不把密钥或上游原始报错中的敏感信息返回给前端。
   - 新增 `GET /api/me/usage`（今日已用/额度），前端设置弹窗显示“今日用量”进度条；写入 `docs/api.md`。
   - 测试覆盖额度超限、限速、用量记录。
7. **配置与文档**：`backend/.env.example` 给出“DeepSeek 对话 + 百炼向量”的完整示例（值留空）；`scripts/dev.sh` 读取白名单加入 `CHAT_[A-Z_]+`、`EMBED_[A-Z_]+`、`TTS_[A-Z_]+`、`IMAGE_[A-Z_]+`、`QUOTA_[A-Z_]+`、`LLM_MAX_CONCURRENCY`；README“配置真实模型”一节改写为分能力配置。
8. **测试**：配置解析与回退、各能力独立切换真实/Fake、DeepSeek 流式忽略 reasoning_content、dimensions 参数与维度探测、`/api/models`、图像 Fake 与 b64/url 解析，全部用 `httptest` 模拟服务端，不调用真实付费接口。
