# GitHub 拉取与 Docker 一键部署

## 服务器前置条件

准备 Git、Docker Engine、Docker Compose 插件（`docker compose version` 可用）、curl、OpenSSL；允许当前用户使用 Docker。建议至少 2 核 4GB 内存，系统及首次构建预留 15–20GB 可用磁盘，上传原件、预览、数据库和备份空间另按资料规模增加。服务器不需要 Go、Node 或 LibreOffice。防火墙与云安全组放行 TCP 80/443，数据库及后端端口不对外开放。

## 首次部署

先在本地把代码推送至自己的 GitHub 仓库。下面操作在服务器执行，替换仓库地址：

```sh
git clone <你的GitHub仓库地址> KnowNote
cd KnowNote
cp .env.example .env
cp backend/.env.example backend/.env
# 分别执行三次，把三个不同结果填入下述配置；不要公开或提交结果。
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

编辑根目录 `.env`：`POSTGRES_PASSWORD` 填第一个随机值；仅 IP 访问时 `SITE_ADDRESS=:80`、`CORS_ORIGINS=http://服务器IP`，`HTTP_PORT=80`、`HTTPS_PORT=443`。必须替换所有尖括号占位符。数据库密码使用十六进制，避免连接 URL 特殊字符转义问题。

编辑 `backend/.env`：`JWT_SECRET` 填第二个随机值，`SETTINGS_ENCRYPTION_KEY` 填第三个随机值，`STORAGE_DRIVER=local`（留空也默认 local）。两种密钥要独立、安全、持久保存；JWT 留空/过短会拒绝生产启动，加密主密钥留空会从 JWT 派生，更换或遗失会导致已有配置密文无法解密。模型 Key 暂时留空，使用 Fake LLM 即可走完整流程。

```sh
chmod 600 .env backend/.env
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
curl -fsS http://localhost/api/health
curl -I http://localhost/
```

首次构建需要下载 LibreOffice 与字体，请等待完成。三个服务应 running/healthy；健康接口应返回 `code=0`、`data.status=ok`、`data.db=ok`。通过 `http://服务器IP` 注册首个账号：`ADMIN_EMAILS` 留空且库内没有管理员时，第一个账号即管理员，请上线后立即注册，避免被他人抢先注册；也可预先填自己的管理员邮箱白名单（逗号分隔）。

登录后进入 `/admin` 填写对话、向量模型密钥与地址，保存前会做连接测试，保存后热更新，无需重启。向量维度必须与 `EMBEDDING_DIM` 一致；切换向量模型后按后台提示重建。TTS、ASR 等非后台配置项通过环境变量设置，修改后重新执行 `up -d`。未配置模型密钥时 Fake 回答仅用于演示。

## 更新与回滚

在服务器仓库目录执行：

```sh
git pull && docker compose -f docker-compose.prod.yml up -d --build
```

回滚到已知提交（替换占位符）：

```sh
git checkout <提交>
docker compose -f docker-compose.prod.yml up -d --build
```

更新与 `down` 不删除数据卷；**不要执行 `down -v`**。默认项目名 `knownote-prod`，更新时保持目录及项目名一致。回滚前备份，旧程序不一定兼容新版数据库结构，必要时配套恢复备份。临时检出后下次更新先切回原分支。

## 域名与 HTTPS

域名 A 记录指向服务器；如有 AAAA，也必须可达。根目录 `.env` 设置 `SITE_ADDRESS=你的域名`（不带协议/路径）、`CORS_ORIGINS=https://你的域名`，公网保持 80/443 可达，再执行 `docker compose -f docker-compose.prod.yml up -d`。Caddy 自动签发续期证书，HTTP 重定向 HTTPS，证书保存在 `caddy-data` 卷。使用自定义宿主机端口时访问 URL/CORS 需带端口，公网自动证书仍要求标准端口可达或另行配置转发。

浏览器麦克风需要 HTTPS 安全上下文；普通远程 IP 的 HTTP 无法录音，语音识别还需要真实 ASR 配置。

## 备份与恢复

以下命令在项目根目录同一个 shell 执行，默认生产项目名；测试或自定义项目只需修改 `PROJECT`。备份暂停后端写入，同时保存数据库逻辑备份及本地数据卷。`backup` 目录含私密资料，应限制权限、异机保存。另行安全保管 `.env`、`backend/.env` 和加密主密钥，不要提交 Git；OSS 使用者还需备份 Bucket。

```sh
PROJECT=knownote-prod
mkdir -p backup
chmod 700 backup
docker compose -p "$PROJECT" -f docker-compose.prod.yml stop backend
docker compose -p "$PROJECT" -f docker-compose.prod.yml exec -T postgres pg_dump -U knownote -d knownote -Fc > backup/database.dump
docker run --rm --network none -v "${PROJECT}_knownote-data:/source:ro" -v "$PWD/backup:/backup" alpine:3.22 tar czf /backup/files.tar.gz -C /source .
chmod 600 backup/database.dump backup/files.tar.gz
docker compose -p "$PROJECT" -f docker-compose.prod.yml start backend
```

恢复会覆盖目标数据库及本地文件，先确认项目与备份配套，并保存目标现状。新服务器先配置相同环境文件与密钥；无需预建库表。下面先只启动数据库，避免应用写入：

```sh
PROJECT=knownote-prod
docker compose -p "$PROJECT" -f docker-compose.prod.yml stop backend web
docker compose -p "$PROJECT" -f docker-compose.prod.yml up -d --wait postgres
docker compose -p "$PROJECT" -f docker-compose.prod.yml exec -T postgres pg_restore -U knownote -d knownote --clean --if-exists --no-owner --exit-on-error < backup/database.dump
docker volume create "${PROJECT}_knownote-data"
docker run --rm --network none -v "${PROJECT}_knownote-data:/target" -v "$PWD/backup:/backup:ro" alpine:3.22 sh -c 'find /target -mindepth 1 -maxdepth 1 -exec rm -rf {} + && tar xzf /backup/files.tar.gz -C /target && chown -R 10001:10001 /target'
docker compose -p "$PROJECT" -f docker-compose.prod.yml up -d --wait
curl -fsS http://localhost/api/health
```

自定义 HTTP 端口时替换最后健康检查地址。不要直接复制运行中的 PostgreSQL 数据目录。Caddy 的 `caddy-data`、`caddy-config` 可按同样 tar 方式在停止 web 后备份恢复，保留证书与代理状态。

## 日志与排错

```sh
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs --tail=100 backend postgres web
docker compose -f docker-compose.prod.yml logs --tail=100 -f
```

- 端口被占：用 `docker ps` 检查映射，调整根目录 `HTTP_PORT`/`HTTPS_PORT`，同步访问地址与 CORS；不要停止不属于本项目的服务。
- 数据库密码改后连不上：`POSTGRES_PASSWORD` 仅在空卷首次初始化生效。恢复原配置即可重新连接；轮换需先在 PostgreSQL 内通过安全交互方式改密码，再同步配置并重建后端。不要删卷解决。
- 构建慢：首次需拉镜像、Go/npm 依赖及 LibreOffice，检查网络与构建输出，不要并发反复重建。OOM 时增加内存/交换空间或在资源充足机器构建匹配服务器架构的镜像。
- unhealthy：检查后端迁移、JWT 必填项、磁盘空间与数据库日志，`docker compose ... logs` 不要公开含敏感信息的输出。
- 麦克风不可用：确认 HTTPS、浏览器权限以及 ASR 配置；只有 Fake LLM 不提供真实识别。

## 镜像与配置说明

后端多阶段构建，运行镜像为 Debian，安装 LibreOffice Writer/Impress/Calc、Noto CJK 字体、curl 与时区数据；以 UID/GID 10001 非 root 用户运行，`/app/data` 与 `/home/knownote` 可写。前端 Node 构建后由 Caddy 提供静态页面，固定真实接口模式 `/api`。环境文件由 `.dockerignore` 排除，镜像不包含真实密钥。

Compose 覆盖后端 APP_ENV、PORT、DATABASE_URL、DATA_DIR、CORS_ORIGINS；根目录 `.env` 控制数据库密码、站点地址、宿主机端口和 CORS。不发布 5432/8080，数据分别保存在 `knownote-pgdata` 与 `knownote-data` 命名卷。

`deploy/Caddyfile` 与 `frontend/deploy/Caddyfile` 必须同步，后者支持独立 `build: ./frontend` 构建上下文。保留 `/api` 前缀，SSE `flush_interval -1`，SPA 路由回退 index.html；上传上限由后端控制（200MB）。8081 仅用于容器内部健康检查，不发布到主机。Compose 默认站点语法 `${SITE_ADDRESS:-:80}`，Caddy 为 `{$SITE_ADDRESS::80}`。

## 本次真实验证记录

2026-11-16，在 macOS 的 Docker Linux/arm64 环境（Engine 29.8.2、Compose v5.5.0）使用临时工作区副本、项目名 `knownote-verify`、HTTP 18081 / HTTPS 18444，模型 Key 留空进行验证。

- 首次尝试约 315 秒后因 Go 官方代理下载 `golang.org/x/time` 出现 HTTP/2 INTERNAL_ERROR 失败；重试后首次成功构建并启动耗时 **410.2 秒（约 6 分 50 秒）**，含失败尝试总计 **745.2 秒（约 12 分 25 秒）**。重试复用了已完成层，并非完全无缓存基准；耗时取决于网络与机器。
- `docker images` 实测：后端 **1.05GB**、web **90MB**、PostgreSQL/pgvector **667MB**；这些是镜像显示大小，不等同下载流量或总磁盘占用。其他架构可能不同。
- 三服务最终全部 running/healthy；健康接口 `code=0`、`db=ok`，首页 HEAD 200，`/notebook/xxx` 与首页 index.html 相同；注册首用户为管理员、登录、创建笔记本、文本来源 ready、`curl -N` SSE `delta/done` 全部通过。
- 后端 UID/GID 为 10001，LibreOffice 7.4.7.2 可用，字体匹配 `Noto Sans CJK SC`。
- `down` 后不重建直接 `up -d --wait`，同账号登录、笔记本和 ready 来源仍在。
- 实际执行本页备份及恢复命令（仅替换项目名和健康检查端口）：备份后修改数据库标题、删除卷内标记，恢复后原标题与文件内容校验均通过，账号与来源可读。
- `bash scripts/check.sh` 通过（Go build/vet/test、前端接口检查和生产构建）；真实 OSS 验证因未配置凭据跳过。真实模型、ASR、OSS 及公网域名证书签发未验证。
- 验证结束仅对 `knownote-verify` 执行 `down -v` 并删除临时目录，未执行全局清理。
