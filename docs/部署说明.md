# 生产部署

服务器需安装 Docker Engine 与 Docker Compose 插件（使用 `docker compose`），并允许外部访问 TCP 80、443。无需在服务器安装 Go、Node 或 LibreOffice。未配置域名时通过 HTTP 和服务器 IP 使用，之后可启用域名 HTTPS。

## 上传仓库

在本地项目根目录执行，替换尖括号占位符；远端目录需预先创建。以下命令不上传本地配置、开发数据和构建产物，也不会删除服务器上手动配置的文件：

```sh
rsync -av \
  --exclude='.git/' \
  --exclude='node_modules/' \
  --exclude='/frontend/dist/' \
  --exclude='/backend/data/' \
  --exclude='/backend/tmp/' \
  --exclude='/backend/bin/' \
  --include='.env.example' --exclude='.env' --exclude='.env.*' \
  ./ '<用户>@<服务器>:<远端目录>/'
```

该命令保留 `.env.example` 配置示例。`.dockerignore` 只控制镜像构建上下文，不控制上传。

## 服务器配置

以下操作均在服务器项目根目录执行。手动创建根目录 `.env`，仅填入自己的值：

```dotenv
POSTGRES_PASSWORD=<强随机十六进制数据库密码>
# 仅用 IP 时保持 :80，或直接省略此项。
SITE_ADDRESS=:80
# 建议填写实际访问来源；只用 IP 时填写 http://服务器IP。
CORS_ORIGINS=http://<服务器IP>
```

数据库密码直接拼入 PostgreSQL URL，建议使用至少 32 字节随机数据的十六进制表示，避免 `@`、`:`、`/`、`#`、`%` 等字符需要 URL 编码的问题。首次初始化后，不要只修改此变量来轮换已有数据库密码。

在服务器将 `backend/.env.example` 复制为 `backend/.env` 后手动填写：

```sh
cp backend/.env.example backend/.env
chmod 600 .env backend/.env
```

生产环境必须填写强随机 `JWT_SECRET`（至少 32 字节）；建议单独填写强随机 `SETTINGS_ENCRYPTION_KEY` 并持久、安全保存，丢失或更换会导致数据库中已有模型与存储密钥无法解密。例如手动编辑以下配置，不能原样使用占位符：

```dotenv
JWT_SECRET=<至少32字节的强随机密钥>
SETTINGS_ENCRYPTION_KEY=<独立生成并持久保存的强随机密钥>
STORAGE_DRIVER=local
```

按需填写模型、语音和 OSS 配置；未配置模型密钥时使用 Fake LLM。`SOFFICE_PATH`、`SOFFICE_FONT_PATHS` 保持空值，镜像自带 LibreOffice 与中文字体。Compose 会覆盖示例中的开发环境、端口、数据库连接、数据目录和 CORS 设置；这些配置以根目录 `.env` 和 Compose 为准。

## 启动与维护

```sh
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs --tail=100 -f
```

停止（保留数据卷）：

```sh
docker compose -f docker-compose.prod.yml down
```

更新：重新执行上传命令，再在服务器运行：

```sh
docker compose -f docker-compose.prod.yml up -d --build
```

生产 Compose 使用独立项目名 `knownote-prod`，不暴露 PostgreSQL 的 5432 或后端的 8080，不复用开发版数据库。不要添加 `down -v`，否则会删除持久数据。

## 验证访问

浏览器访问 `http://<服务器IP>`。健康检查使用真实 API 路由：

```sh
curl -fsS 'http://<服务器IP>/api/health'
```

正常返回 `code=0`，且 `data.status`、`data.db` 均为 `ok`。首次启动需等待数据库健康与后端迁移完成。未配置 `ADMIN_EMAILS` 且库内没有管理员时，第一个注册账号成为管理员；配置邮箱名单时按名单授予管理员权限。

登录后检查上传、同源 iframe 原件预览和对话流式显示。Caddy 保留 `/api` 前缀，设置 `flush_interval -1`，不限制请求体大小；上传上限由后端控制（最大 200MB）。前端固定构建为真实接口模式，接口地址为 `/api`。

## 域名与 HTTPS

将域名 DNS 解析到服务器，确保 80、443 可访问；如设置 AAAA 记录，也应指向这台服务器可访问的 IPv6 地址。在根目录 `.env` 修改：

```dotenv
SITE_ADDRESS=<域名>
CORS_ORIGINS=https://<域名>
```

域名只填主机名，不带协议或路径，例如示例域名 `knownote.example.com`。然后运行：

```sh
docker compose -f docker-compose.prod.yml up -d
```

Caddy 自动签发、续期证书并将 HTTP 重定向到 HTTPS，证书保存在 `caddy-data` 卷。浏览器麦克风（语音输入）需要 HTTPS 安全上下文，普通远程 IP 的 HTTP 页面无法使用麦克风；同时后端需要配置真实 ASR 服务。

## 数据备份

必须同时备份 `knownote-pgdata`（数据库）和 `knownote-data`（上传原件、预览等本地文件）。实际 Docker 卷名带项目名前缀，默认分别为 `knownote-prod_knownote-pgdata`、`knownote-prod_knownote-data`。为保持数据库与文件一致，备份期间暂停写入；数据库使用 `pg_dump` 逻辑备份或停库后的卷快照，不要直接复制运行中的 PostgreSQL 数据目录。

另行安全保存两个环境配置文件和加密主密钥；使用 OSS 时还需备份 Bucket 数据。`caddy-data`、`caddy-config` 可一并备份以保留证书与代理状态。恢复时保持数据库、文件和加密密钥配套。

## 镜像与配置说明

后端安装 LibreOffice Writer、Impress、Calc 与 CJK 字体，镜像体积约 1GB 量级，以实际 `docker images` 的 SIZE 为准。后端以非 root 用户运行，`/app/data` 和 `/home/knownote` 均可写，后者供 LibreOffice 保存配置。镜像不包含环境配置文件。

根目录 `deploy/Caddyfile` 与 `frontend/deploy/Caddyfile` 内容必须保持一致：前者用于独立校验，后者用于 `build: ./frontend` 和 `docker build ./frontend`，因为 Docker 不能复制构建上下文以外的文件。更改代理配置时同步修改两份，再重新构建 web 镜像。

Compose 的默认地址写作 `${SITE_ADDRESS:-:80}`（默认值为 `:80`），Caddyfile 对应 `{$SITE_ADDRESS::80}`，两者变量语法不同。
