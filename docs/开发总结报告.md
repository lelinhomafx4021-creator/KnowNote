## 1. 项目概览与建设目标

**知页 KnowNote** 是一款仿 Google NotebookLM 体验的个人智能资料管理与学习辅助系统（毕业设计项目）。系统围绕“笔记本”工作台组织个人多格式资料，实现从**多格式入库解析 → 中文文本切分与向量索引 → 可追溯引用 RAG 问答 → 面向教学与学习的多形态产物生成导出 → 管理员集权热更新与额度审计**的完整工程闭环。

### 核心技术栈

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 前端展示与状态 | React 18、TypeScript、Vite、Tailwind CSS、Zustand | 三栏工作台（来源/对话/工作室）、独立宣传落地页 `/welcome` 与登录页、管理后台 `/admin` |
| 后端服务 | Go 1.27、Gin、GORM | 单进程分层服务（handler / service / rag / parser / llm / exporter / storage / settings） |
| 数据与向量存储 | PostgreSQL 16 + `pgvector`（HNSW 余弦索引） | 业务表与 1536 维向量同库事务存储，总计 16 张核心数据/运维表 |
| 模型与扩展能力 | OpenAI 兼容协议 + 确定性 Fake 模型 | DeepSeek 对话、阿里云百炼 `text-embedding-v4`、可选 TTS 语音与内部 `ImageClient` 扩展点 |
| 文档解析与导出 | PDFium WASM、纯 Go OOXML 构建/解析、LibreOffice (`soffice`)、excelize | 原件解析、在线 PDF 预览与教学产物 `.pptx` / `.docx` / `.pdf` / `.md` 导出 |
| 文件存储 | 本地受限 `os.Root` / 阿里云 OSS v2 SDK | 支持 `Range 206`、预签名跳转与异步删除重试日志 |

## 3. 核心架构与收尾增强亮点

系统整体分层架构与数据流详见 [架构设计.md](架构设计.md)。收尾阶段围绕真实使用场景（尤其是教师备课与多角色管理）完成了以下三项关键增强：

### 3.1 NotebookLM 风格界面与独立宣传着陆页
- 新增品牌宣传首页（`/welcome` 路由及未登录根路径 `/`），介绍知页的核心能力（多格式解析、可追溯引用问答、教学文稿工作室），并提供一键跳转登录/注册流程，替代了原先直出空白表单的冷启动体验。
- 对齐 NotebookLM 视觉规范，重构登录页布局与双色调矢量功能图标（`FeatureIcons.tsx`），优化暗色/亮色主题、圆角层次及移动端三栏切换。

### 3.2 工作室教学多格式生成（PPT / Word / PDF）与宽屏预览交互
面向教师高频制作课件、教案与讲义的需求，右侧工作室重构为“**主要格式导出（PPT / Word / PDF） + 学习辅助工具（导图/指南/简报/FAQ/时间线） + 音频概览**”：
1. **紧凑工具网格与自定义生成面板（`StudioGenerateModal`）**：
   - 备课文件生成区采用与思维导图一致的紧凑双列小块网格；
   - 点击任意小块（或专题工具右侧配置按钮）弹出定制面板：**默认勾选全部可用来源并支持逐项删减**，同时支持设定用途场景、篇幅/页数、目标受众、内容侧重与具体要求（附一键快捷提示），精准控制 RAG 检索范围与成稿风格。
2. **双模式检索生成**：
   - 支持直接基于选定来源摘要生成（`retrievalMode: "summary"`）；
   - 也支持输入具体主题或备课要求（`topic` + `preset` 预设用途），后端调用 `Client.Embed` 与 `rag.Retriever.Search` 在本次选定来源的 pgvector 向量空间内检索最相关片段后再结构化生成（`retrievalMode: "rag"`）。
3. **自动宽屏展开与实时预览**：
   - 点击右侧「产物与笔记」中的任意条目（PPT、Word、PDF、思维导图或笔记）进入查看时，右侧工作室面板自动宽屏展开（`58%`，支持「宽屏预览 / 收窄面板」随时切换）；
   - 生成 `kind = "ppt"` 时产出结构化 `SlideDeck`（含章节板式、核心要点、演讲者备注 `notes`），`SlideDeckViewer.tsx` 提供 16:9 渐变舞台画布与方向键翻页；`PDF 讲义` 进入预览时自动加载内嵌 PDF 排版视图。
4. **纯 Go OOXML 构建与 LibreOffice PDF 渲染（`backend/internal/exporter`）**：
   - `BuildPPTX` 与 `BuildDOCX` 生成真实可二次编辑的 `.pptx`（16:9 宽屏与演讲备注）与 `.docx` 文件；
   - `ToPDF` 通过 `parser.Convert`（LibreOffice headless + 中文字体映射）转换为排版规整的 PDF；
   - 新增 `GET /api/artifacts/:id/export?format=...` 与 `GET /api/notes/:id/export?format=...` 鉴权导出接口，支持产物与笔记的跨格式导出下载（如 PPT ⇄ PDF ⇄ Markdown、思维导图 ⇄ Word/PDF/OPML 样式 Markdown）。

### 3.3 管理员唯一模型与普通用户彻底脱敏
落实“**所有模型和系统配置仅管理员可操作、普通用户不展示任何模型信息**”的权限边界：
- **接口级拦截与字段隐藏**：`GET /api/models` 挂载 `middleware.ActiveUser(s.DB, true)` 强制要求 `role == "admin"`，普通用户访问返回 `403`；`PATCH /api/me/settings` 检测到 `model` 字段时返回 `403`（业务码 `40301`：“仅管理员可配置模型与系统参数”）；`SettingsView.Model` 标注 `json:"model,omitempty"`，非管理员请求 `/api/me/settings` 响应 JSON 中完全省略 `model` 字段，所有调用统一收敛至系统全局激活模型。
- **前端界面隐藏**：普通用户在设置弹窗仅保留“回答风格 / 回答语言 / 界面主题”、不涉及模型字样的「今日服务额度」与登录记录，完全不展示任何模型名称、切换入口或管理员提示；模型切换与 `/admin` 控制台仅对管理员开放。

## 4. 安全隔离与稳定性机制

| 维度 | 实现方案 |
|---|---|
| 身份认证与实时状态 | HS256 JWT（7 天有效）；所有业务请求查库校验用户 `disabled` 与最新 `role`，停用或撤权对已有旧 Token 立即返回 `403` |
| 租户隔离 | 全量业务 SQL 强制附带 `user_id` 条件，数据库建立 `(user_id, id)` 等复合外键；跨用户访问统一返回 `404` |
| 认证安全与限流 | bcrypt 密码哈希；登录/注册审计（`login_logs`）；基于数据库邮箱级事务锁的 10 分钟内 5 次失败触发 `429` 限流 |
| 密钥与存储安全 | 模型密钥经 SHA-256 + AES-GCM 密文入库 `system_settings`，接口与日志只展示掩码或来源标签；本地文件访问受 `os.Root` 与路径校验约束；网页抓取校验公网 IP 防止 SSRF |
| 额度与并发 | `llm.Guard` 基于用户级数据库 advisory 事务锁预留 Token 与请求配额，支持每日总额度与每分钟频率限制 |

## 5. 全量验证结论（2026-11-15 实测）

1. **后端完整测试与静态检查**：
   - `cd backend && go vet ./...` 退出 `0`；
   - `DATABASE_URL=postgres://knownote:knownote@localhost:5432/knownote?sslmode=disable go test -count=1 -v ./...`：**12 个测试包共 76 个顶层测试 `PASS`（0 `FAIL`）**，涵盖 `exporter` OOXML/PDF 转换、RAG 检索、多格式解析、额度并发锁、热更新、初始笔记自动发放（`TestStarterNotebookOnRegisterAndSamplesList`）与精选示例清单校验（`TestLoadCuratedManifests`）以及 `403` 管理员隔离集成测试；仅 `TestRealOSS` 因未启用/配置真实云端 OSS 凭据按约定 `SKIP`。
2. **前端接口验证与生产构建**：
   - `cd frontend && npm run test:api`：SSE UTF-8/CRLF 分包、取消状态隔离、预览与鉴权传输校验通过；
   - `cd frontend && npm run build`：`tsc -b` 与 `vite build`（1892 modules）编译通过。
3. **真实环境前后端启动冒烟与数据收尾**：
   - 清理开发/验收过程中产生的历史测试账号、`login_logs` 测试流水与孤儿上传目录，并移除前端演示数据中的偏题示例；
   - `FRONTEND_PORT=5174 ./scripts/dev.sh` 成功拉起服务（实配 DeepSeek Chat + DashScope `text-embedding-v4`），内置 `4` 套精选示例笔记（`knownote-guide` / `llm-rag-intro` / `thesis-writing` / `study-methods`）全部就绪；

## 6. 已知限制与后续展望

1. **解析与媒体能力边界**：不支持扫描版 PDF 的 OCR 识别；旧版 `.doc`/`.ppt`/`.xls` 依赖本机存在 LibreOffice；音视频文件当前不执行语音识别转写；网页抓取引自 `go-readability` 静态解析，不执行 JS 或登录拦截页面。
2. **外部付费服务验证边界**：阿里云真实 OSS Bucket、独立付费 TTS 语音 MP3 播放解码，以及未配置真实模型 Key 时的 Fake 模式语义评测仍属部署/扩展范围。
3. **部署拓扑与生命周期边界**：后台入库队列、音频生成任务及热更新原子句柄当前面向**单进程部署**；JWT 未设服务端即时注销黑名单；`storageTotal`（5 GiB）用于展示统计，当前不作硬性拦截。
4. **后续演进建议**：接入图片业务表与工作室“封面/信息图”生成 UI（复用既有 `ImageClient`）；支持扫描件 OCR 与音视频自动转写；引入轻量分布式锁实现多实例水平扩展。
