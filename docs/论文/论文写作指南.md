# 毕业论文写作指南：基于大语言模型的个人资料管理系统

> 本文件说明论文怎么写、每章写什么、需要哪些图表，以及项目里哪些现成材料可以直接用。
> 写正文前先确认学校的**论文模板、字数要求、参考文献格式**（一般为 GB/T 7714—2015），以模板为准调整章节名。

## 一、论文题目（任选其一）

1. 基于大语言模型的个人资料管理系统的设计与实现（推荐，常规、稳妥）
2. 基于检索增强生成的个人知识库问答系统设计与实现（突出 RAG 技术）
3. 面向多格式文档的智能资料管理与问答系统的设计与实现

题目里“设计与实现”是工科本科最常见的写法，论文结构就按“需求 → 设计 → 实现 → 测试”展开。

## 三、章节大纲与写作要点

### 摘要 / Abstract
- 第一句写背景：个人学习资料多、格式杂、难检索；通用大模型回答没有出处、容易“幻觉”。
- 中间写做了什么：设计并实现了一个类似 NotebookLM 的系统，支持 PDF / Word / PPT / Excel 等资料上传、基于检索增强生成（RAG）的带引用问答、学习资料自动生成。
- 写技术：React + TypeScript 前端，Go + Gin 后端，PostgreSQL + pgvector 向量检索，DeepSeek 对话模型，阿里云百炼 text-embedding-v4 向量模型。
- 最后写效果：用测试数据说话（例如检索命中率、首字响应时间约 2 秒、功能测试用例全部通过）。
- 关键词 3～5 个：大语言模型；检索增强生成；向量检索；个人知识管理；pgvector。

### 第 1 章 绪论
1.1 研究背景与意义：信息过载、资料分散；大模型的能力与“幻觉”问题；为什么需要“基于自己的资料回答且可追溯”。
1.2 国内外研究现状：
- 个人知识管理工具（Notion、Obsidian 等）——能存不能“懂”；
- 大模型问答产品（ChatGPT、文心一言等）——能答但无出处；
- RAG 方向的研究（Lewis 等 2020 年提出 RAG）与产品（Google NotebookLM、各类知识库问答）；
- 向量数据库的发展（Milvus、pgvector 等）。
- 写法：每类说清“做到了什么、还缺什么”，最后一段引出本课题要解决的问题。
1.3 主要研究内容：分条列出（多格式解析、RAG 问答与引用溯源、学习资料生成、多用户与安全、多模型接入）。
1.4 论文组织结构：每章一句话。

### 第 2 章 相关技术
只写系统真正用到的，每项写“是什么 + 为什么选它 + 在本系统怎么用”：
2.1 大语言模型与 DeepSeek（推理模型、流式输出）
2.2 检索增强生成 RAG（流程：切分 → 向量化 → 检索 → 生成）
2.3 文本向量化与向量检索（嵌入模型、余弦相似度、HNSW 近似最近邻索引）
2.4 PostgreSQL 与 pgvector（为什么不用 Milvus：业务数据与向量同库、事务一致、部署简单）
2.5 Go 语言与 Gin 框架
2.6 React 与 TypeScript、Tailwind CSS
2.7 SSE 服务器推送（为什么用 SSE 而不是 WebSocket）
2.8 JWT 身份认证
2.9 本章小结

### 第 3 章 需求分析
3.1 可行性分析：技术可行性、经济可行性（模型按量计费、成本很低）、操作可行性。
3.2 用户角色：普通用户、管理员（T11 完成后）。
3.3 功能需求：配**用例图**，并逐个写用例描述表（用例名、参与者、前置条件、基本流程、异常流程）。建议写 6～8 个核心用例：注册登录、笔记本管理、上传来源、带引用问答、保存笔记、生成学习资料、查看原件、系统配置。
3.4 非功能需求：性能（首字响应、入库耗时）、安全（密码加密、数据隔离、密钥不下发前端）、可用性（深浅色、移动端）、可扩展性（模型可替换、存储可切换本地或 OSS）。
3.5 本章小结

### 第 4 章 系统设计
4.1 总体架构设计：分层架构图（表示层 / 接口层 / 业务层 / 数据层 / 外部模型服务）。
4.2 功能模块设计：**功能模块图**（用户、笔记本、来源、问答、工作室、笔记、系统管理）。
4.3 关键流程设计：
- 来源处理流程图（上传 → 解析 → 切分 → 向量化 → 摘要 → 就绪）；
- RAG 问答**时序图**（前端 → 后端 → 向量库 → DeepSeek → SSE 回前端）；
- 引用溯源设计（编号、页码、跳转原文）。
4.4 数据库设计：**总体 E-R 图**、**各实体属性图**（拆分后的分图）、**数据表结构**（每张表一个表格：字段、类型、约束、说明）。
4.5 接口设计：RESTful 约定、统一响应格式、主要接口表（可从 `docs/api.md` 精简）。
4.6 安全设计：JWT、bcrypt、按用户隔离、文件签名链接、调用额度与限速。
4.7 本章小结

### 第 5 章 系统实现
每个模块按“功能说明 → 界面截图 → 关键实现（流程 + 少量核心代码，每段不超过 20 行）”来写：
5.1 开发环境（硬件、操作系统、Go / Node / PostgreSQL 版本、开发工具）
5.2 用户注册与登录
5.3 笔记本管理（首页）
5.4 多格式资料解析（PDF 按页、PPT 按幻灯片、Word 标题与表格、Excel 按工作表、旧版格式转换）
5.5 文本切分与向量化入库
5.6 带引用的智能问答（检索、提示词、流式输出、引用编号）
5.7 原件预览与引用定位
5.8 学习资料生成（学习指南、FAQ、时间线、思维导图、音频对谈稿）
5.9 多模型接入与调用额度
5.10 本章小结

### 第 6 章 系统测试
6.1 测试环境与方法（黑盒功能测试 + 自动化单元/集成测试）
6.2 功能测试：用例表（编号、模块、操作步骤、预期结果、实际结果、结论），可直接从 `docs/测试报告.md` 整理。
6.3 性能测试：入库耗时、检索耗时、问答首字时间（已有实测数据）。
6.4 **检索与问答效果评估（加分项，建议做）**：
- 准备 3～5 份资料、30 道问题，人工标注每题的正确出处；
- 统计检索命中率 Recall@6（正确片段是否在前 6 个里）；
- 统计引用准确率（回答中引用的片段是否真的支持该句话）；
- 对比：真实向量模型 vs 关键词/离线向量，体现 RAG 与向量模型选型的价值。
6.5 测试结论

### 第 7 章 总结与展望
- 总结：完成了哪些功能、解决了什么问题、有什么特色（引用可追溯到页码、多格式、多模型可替换）。
- 不足与展望：扫描件 OCR、更大规模资料的检索性能、对话记忆、移动端 App、团队协作共享。

### 参考文献（建议 15～25 篇，近 5 年占多数，含外文 3～5 篇）
可以引用的方向：RAG 原始论文（Lewis 等，2020）、Transformer（Vaswani 等，2017）、Dense Passage Retrieval（Karpukhin 等，2020）、HNSW（Malkov 等，2018）、大模型幻觉综述、国内知识库问答相关期刊论文、pgvector / PostgreSQL 官方文档、DeepSeek 技术报告。**每一篇都要自己在知网 / Google Scholar 核实后再写入，不要直接用 AI 给出的文献信息。**

## 五、写作注意事项

1. **先图后文**：先把架构图、E-R 图、流程图、截图准备好，再围绕图写文字，写起来快很多。
2. **代码少而精**：正文只放核心逻辑片段，配文字解释“为什么这样做”，不要整页贴代码。
3. **用数据说话**：性能、检索命中率、测试通过数都要有具体数字和表格。
4. **术语前后一致**：如“来源”“片段（分块）”“笔记本”“引用”，第一次出现时给出定义。
5. **答辩会问的问题要在论文里有答案**：为什么用 RAG 而不是微调？为什么选 pgvector？怎么避免模型编造？文档怎么切分、为什么是 500 字？多人使用怎么控制成本？
6. **AI 使用说明**：本项目大量代码由 AI 辅助生成，请确认学校政策；很多学校要求在论文中说明 AI 工具的使用方式与范围。正文文字要用自己的话写，并通过学校查重。
7. **参考文献必须真实**：逐篇核实标题、作者、年份、期刊，按 GB/T 7714 格式排版。
